# E1–E4 reproducible engineering experiments

These scripts exercise the built project without changing production code or dependencies. The ML text is self-authored **engineering fixture data**, not a scientific dataset or measured ML result. `service` uses real ResearchApp services and isolated temporary SQLite databases, with deterministic submitted outputs and reviewer verdicts. It does not call an LLM, model runtime, network, Docker, browser or PDF parser. Temporary service databases are removed after each case; JSON keeps the relevant IDs, state, source bytes and observations.

Run from any directory, supplying the frozen, cleanly built project root. The runner changes its cwd to that root before loading the existing research test helper, so template and skill lookup match the runtime. Use the same Node version as the project. No installation is performed.

```powershell
node scripts/contest-e1-e4/selftest.mjs
node scripts/contest-e1-e4/run.mjs --root '<frozen-runtime-root>' --out '<new-output-dir>/graph' --phase graph
node scripts/contest-e1-e4/run.mjs --root '<frozen-runtime-root>' --out '<new-output-dir>/service' --phase service
node scripts/contest-e1-e4/run.mjs --root '<frozen-runtime-root>' --out '<new-output-dir>/benchmark' --phase benchmark
```

`--phase all` runs all three phases in a new directory. Every evidence directory must be new: existing output is rejected before any write. Incremental runs use new phase subdirectories. Failed service cases retain their observations and assertion errors in JSON. Manifests record Node/platform, timestamps, runtime and runner hashes; the parent delivery record must identify the frozen source snapshot because HEAD alone does not describe uncommitted source changes.

- **E1**: 5 hand-labelled graphs plus 80 fixed seeds × 4 categories (325 cases). A monotone event simulator tracks submitted and accepted sets, assuming all executions and reviews succeed. It computes liveness independently of production DFS/event-graph validation. Task-only reachability is used only to split a stuck case into ordinary cycle versus review-stage deadlock. Unknown dependencies are a separate input-validity category. Input, intended label, oracle rounds, production returned graph/error and confusion counts are retained. The weaker Kahn/fixed-point task-DAG baseline checks dependencies plus reviewOf and intentionally misses acceptance-stage deadlocks. All other generated input fields are valid; this is not an exhaustive schema-fuzzing test.
- **E2**: producer stays pending until review; all declared reviewers must accept; conflicting votes dispute the producer; partial producer output cannot be manually accepted; failed review attempt blocks downstream. Each case uses actual TeamService transitions, approval and claim APIs in a fresh database. Output is deterministic service-fixture data, not autonomous agent execution.
- **E3**: V=4/8/16/24; 32 legal fixed-seed graphs per V; 1024 warm-up calls per implementation; 30 timed batches × 1024 calls, alternating implementation order. Raw total ns, per-call ns, median and nearest-rank p95 are retained. Median is the average of the two central values for 30 samples. Production absolute overhead is primary. The weaker task-only baseline omits schema and event checks; **do not report a speedup ratio or infer overall scheduler acceleration**. Results depend on host load/JIT/GC and are not confidence intervals or independent process replicates.
- **E4**: exact UTF-16 citation and original UTF-8 bytes; identical-title/different-content artifact identity; old evidence and fixed report reference retain original text; corpus removal/disable rejects new retrieval while preserving historical evidence/report; CAS byte corruption rejects cached retrieval and a new claim; database close/reopen preserves original artifact/evidence/search/report/reference IDs and bytes. Corpus eligibility changes are not scientific invalidation or task-source revocation. Source-revocation propagation, browser, model, PDF parsing and PDF export are outside this experiment.

`selftest.mjs` checks the pure oracle against explicit counterexamples and all deterministic generated labels, verifies repeatable generation and summary percentile conventions. It also runs an isolated fake accept-everything validator and requires E1 `passed=false`, runner exit 1 and a failed manifest; production modules are untouched. The main runner asserts both graph and service outcomes; failure exits nonzero after saving observations. E3 asserts graph validity before timing and retains every batch rather than discarding outliers.
