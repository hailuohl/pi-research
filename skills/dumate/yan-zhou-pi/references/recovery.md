# 历史保留、备份与重开

所有新功能继续沿冻结helper的一工作区唯一写锁、原子新目录、失败/中断保留机制；历史摘要只是文件一致性校验，不是服务端CAS、事务、撤权传播或防篡改签名。

重开先执行 `python scripts/workflow_status.py status --workspace 工作区 --task T1`。它只读核验当前任务所有新旧step及其依赖扩展代码、输入、输出；返回真实失败、invalid、interrupted、pending和锁，不清理或重启。旧research.status仍可读旧记录，但不能用它代替新扩展模块代码链核验。

相同命令/ID仅在所有摘要、参数和代码仍匹配时复用，不重分析已有结果。变更的输入另存inputs新文件、方法/代码/参数另选新步骤ID；更新安装包前保留原包，旧代码绑定的结果使用其原发行包回查。不要修改旧source、receipt、图或稿件来消除invalid。

用户已选定备份位置时，用当前已授权的文件工具复制整个工作区到全新目录，并逐文件核对相对路径/尺寸/SHA；inputs、project、tasks、失败/中断、原版脚本安装包和简短清单一起保留。备份期间停止写入或取一致的只读副本；不要把运行中复制当完整快照。不从安装包目录反向覆盖研究目录，不把原始数据/对话上传Git或对外发布。

遇到锁/pending，先确认原进程/原生会话实际状态和现有产物。观察超时不表示进程失败；继续等待同一进程，不能再次启动同一任务。确认终态后，按已有人工恢复流程保留原尝试和锁证据，再决定新版本或恢复工作副本；本包没有自动删除锁、抢占、回滚或续跑后台作业能力。不知道状态时保持阻断，不能将未决产物标complete。

严格修订分源稿与新排版两阶段：源稿成功、排版失败时源稿仍可校验，保留旧格式稿与失败记录，重开只处理尚未完成阶段。新稿科学/页面意见重新实际检查；旧pass仅属于旧文件。
