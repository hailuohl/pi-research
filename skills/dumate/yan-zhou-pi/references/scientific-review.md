# 科学核对与限定修订

起草科学结论、检查论文或按意见修订时读取本文。只处理当前任务明确选定的来源、数据和稿件；不启动Pi、研舟服务、研究数据库或外部模型执行器。已有授权范围内的核对与修正继续进行，不要求用户逐条审批内部记录。新的材料、分析或研究方向不由本文自动授权。

## 核对实际主张

先读取当前稿的 `paper_context.json`、`draft-source.md`、`manuscript.md`、引用映射，以及主张所需的选定原文、证据上下文、`result.json` 和图注。文件摘要、引用ID、生成成功或上一轮总结不能代替阅读。逐条记录关键主张在章节/句子/图表中的位置、实际来源位置和值、适用条件、发现及未覆盖范围；记录放当前任务的独立检查文件，不加入论文正文。

- **数值与比较方向**：结果从真实输出读取，核对组别、指标定义、有效样本数、精度，以及比较是A−B还是B−A。先确定指标应增大还是减小，再判断更好/更坏；参照组、效应方向、区间与文字必须一致。
- **单位与量纲**：区分比率和总量、百分比和百分点、归一化值和原值；金额、能量、效率等依照实际定义。没有来源依据不换算、不补单位。
- **统计解释**：原research.py analyze仅描述统计；均值差和样本SD不证明显著、置信区间或因果。新统计入口按 [statistics.md](statistics.md) 只执行另有授权、计划许可的明确方法；核对原/校正p、完整族、假设、单位、差值方向和区间定义。不因科学核对新增检验或重算用户既有结果。舍入p=0.05不能断定严格小于0.05；p=0不表示真实概率精确为零。
- **条件与结论范围**：结论只覆盖实际样本、条件、时间窗和对照；平均改善不能改写为每个条件都有效。分别说明观察、关联、因果和待验证机制。有限搜索的最好结果不称全局最优，事后评价指标不冒充原优化目标。
- **证据与反例**：区分元数据、摘要、全文和视觉观察；回读原话前后文，核对作者限制与相反结果。自动引用/数值标记只核对映射，不能证明语义支持。

交叉检查摘要、结果、图注、讨论和结论，避免只修正一处而保留别处的同一错误。缺原值、方法、条件或来源时记录具体缺口；不凭常识补数，不将未核对项记为pass。

## 检查记录与真实审阅者

旧稿沿用README的scientific检查结构；复杂新稿/格式稿按 [current-review.md](current-review.md)，绑定当前MD/context及实际来源摘要。notes说明主张位置、来源和值、发现及未覆盖范围。另存详细发现时给出任务内路径与摘要。确定错误记fail，缺关键来源或结论仍冲突记pending；只在实际范围核对完且无阻断后记pass。

明确记录实际执行者和 `self_check` 或 `independent_review`。同一会话的二次自查仍是self_check；没有真实独立审阅者就记录not_performed。独立审阅者也要读取当前稿与实际来源，指出具体句子、来源位置、错误及影响；没有收到图片不得声称看过页面。代码核对通过不代表科学审阅通过。

科学核对、限定修订范围、文档导出、图像/PDF视觉检查和独立审阅分别报告。旧稿的检查不能批准新稿；排版草稿、formatted文件及平台发布副本另按论文交付方法核对。

## 按明确清单限定修订

以下为冻结1.0.2正文/context不变流程。需要获准题名或当前任务已有证据/结果选择修订时，使用 [revision-workflow.md](revision-workflow.md) 的新严格入口；它保持原来源范围和身份，不重分析数据。新源稿再经document_workflow另存排版，以current-review重新核对。

1. 回读固定原稿 `manuscript/<原稿ID>/draft-source.md` 与全部必要来源，记录原始字节的SHA256。修订的是含引用/数值标记的正文源码，不编辑已生成的参考文献、receipt、PDF或发布副本。缺基线或无法读全时先说明缺口，不承诺未改部分保持。
2. 在用户已有修订范围内列出具体old/new替换或删除，注明位置；同一错误出现在范围外时先交主协调者决定是否属于当前授权。所有位置以原基线为准，不能用逐次替换后移动的位置。保留负结果、限制、引用、科学符号和未触及内容；不以语义相同代替逐字节保持。
3. 把清单和候选新源码另存为明确选择的 `inputs/` 文件，用原 `research.py manuscript` 创建全新的稿件ID，沿用原选定上下文。不要覆盖旧稿或重做已有分析；不只交修正段落，不在保留错误原句后追加一个正确句。
4. 用下面的 `check_revision.py` 对照原稿、新稿和清单。只有actual新源码恰好等于清单生成的expected字节，且选定上下文不变，才记录范围pass；失败新稿保持但不得作为已完成修订交付。修正候选或清单另存新版本，不削弱核对。
5. 回读新稿、真实diff与核对记录，确认错误被替换/删除、没有额外修改。重新科学核对，并检查新DOCX/PDF。当前包确实提供且已验收的article排版命令才可用于新稿，另建格式版本；否则保留在途排版工作并说明当前能力缺口，不调用尚未交付的命令。旧排版版本、旧检查与旧成果保留。

### 核对器接口

```text
python 包目录/scripts/check_revision.py --workspace 工作区 --task T1 --baseline V1 --paper V2 --id R1 --spec inputs/edits.json
```

`V1`和`V2`均为原helper已生成的manuscript稿件，`R1`是全新的修订核对版本。核对器只读两稿和所选清单，在 `tasks/T1/revisions/R1/` 保存实际范围、摘要及diff，复用原helper的唯一写锁、失败保留与重开机制。它不执行研究、不修改两稿、不更新科学或视觉检查，也不证明替换内容正确。执行结果complete仅表示机械范围核对完成。

清单格式：

```json
{
  "baseline_sha256": "原稿draft-source.md原始字节的实际SHA256",
  "edits": [
    {"start": 0, "old": "该位置的精确原文", "new": "替换文本；删除时为空字符串"}
  ]
}
```

`start`是原始UTF-8文本解码后的0起始Unicode码点位置，不是字节或UTF-16位置；读取原始字节后解码，不转换CRLF换行。old必须非空且与该位置完全匹配，new必须不同；核对器记录old在基线中的实际匹配总次数，重复句由start消歧。清单不得重叠或为空。新稿的 `paper_context.json` 必须与原稿逐字节相等；增加来源、改变分析或调整上下文属于新的研究范围，不能冒充这条限定修订流程。

新核对版本固定基线、新稿、清单及核对器摘要。重开先用原helper的status检查文件，再以相同核对器调用校验复用；改清单、候选稿或核对器使用新ID，不能用旧pass批准新内容。锁或pending未清楚时先查原进程，不自动删除或抢占。
