# 成本收益与原始运行前沿

前沿用于展示两个目标的取舍，必须先声明方向和单位。`pareto.py` 读取 method,setting,seed,kl,reward，以 KL 最小、reward 最大为优。保留 DATA、METHODS 和 load(path)。METHODS 默认 {GRPO:(blue,o), ES:(red,D)}，可配置每方法的色板颜色名和 marker；原始点与前沿均保留形状冗余，灰度与色觉差异下也可区分。load 返回 {method:(kl数组,reward数组,不同setting数)}，保留原行顺序。每个原始独立 run 都以淡色散点显示；每个方法用它的全部原始点单独计算并连出非支配前沿，不能先按 setting 求均值再画另一种含义的前沿。

图例标明每方法实际 run 总数与 setting 数，stdout 列出每方法实际 run 总数和不同 setting 数，不假称各 setting 的重复数相同。重复 method/setting/seed 明确拒绝，非有限坐标也拒绝；单 run 是一个可显示的观测，不伪造重复或误差棒。当前模板不从原始点的包络推断均值置信区间，也不把不同方法混成一条前沿。

`pareto_front(x,y,minimize_x=True,maximize_y=True)` 接受两组等长有限一维数据，返回原始整数索引，按方向转换后的有效 x 成本升序。四种方向均支持；相同 x 只留更优 y，完全重合点保留原顺序首个代表；空输入返回空整数数组。方向由研究问题决定，不能为获得有利前沿而切换。

原始 run 的前沿反映已观测到的非支配结果，不证明方法间有统计上确定的优劣。极端随机结果可能进入包络，连接线也不表示两点之间一定存在可行配置。图注应交代独立单位、设置范围和重复数；如果研究需要均值前沿或风险约束，须明确另行定义，不能悄悄替换本模板语义。
