# v0.2.2 固定修复基线

这是 v0.2.1 的修复版，不包含外部项目吸纳。保留 Pi 唯一内核、独立 Runner、现有实验与证据对象。本版将在增强之前独立归档。

## 修复
- F21：重试保持显式暂停，不自动恢复其他任务；激活、恢复、领取均核验当前计划批准与输入。旧批准失效后需新建并批准计划。
- F22：归档与新提交同一事务检查；归档使未消费批准失效、取消排队消息。Run 准备/提交/领取/监管启动拒绝归档后的新操作。已发生 Run、报告和合法重复响应继续可读。
- F23：任务产出的 Claim 绑定不可变 AcceptanceRecord（任务尝试、结果、输入、依赖和审查依据）；revise 保留历史 status，但标记当前 validity=stale。新报告拒绝失效结论。
- F24：撤销 Reviewer 向生产者、其他审查、下游及显式跨团队证据依赖传播。旧代码提案失效；已应用的子实验保留，但不能据此再准备新 Run。
- F25：必需审查失败且无任务可推进时暂停并只通知一次；重试后仍需显式恢复。不为了结束而自动接受生产结果。
- UI 显示历史失效 Claim / 提案。报告表单明确排除失效结论；后端仍重新检查，前端不能代替权限。

## 兼容与升级
停止旧控制服务、Agent 与 Runner 的写入，备份整个数据目录。用本版指向相同绝对 PI_DATA_DIR；不要同时运行两个版本或随意移动旧数据。
新增字段为兼容 JSON 字段和 acceptance-record 记录。没有删除旧原文、审查、任务提交、Run 或报告。旧任务型已采纳 Claim 若缺少新绑定，需重新核验后人工采纳；原任务失效时不能直接重置旧结论，须新任务。旧的任务产物提案缺少绑定时，应重新准备并批准。普通用户原始文件不虚构任务审查记录。
这不是任意路径/跨 OS 迁移或通用降级保证。比较两个版本应分别使用独立数据目录和测试输入，不共享数据库。

## 执行
```
node dist/apps/cli/index.js doctor
node dist/apps/server/index.js
node dist/apps/cli/index.js demo-campaign
```
核心 Node >=22.16；真实 Pi 仍需 >=22.19、固定 SDK 和模型凭据。预构建核心不需 npm install。
