# Pi Research v0.2.0 Implementation Plan

> Execute inline, test-first. This plan extends the supplied v0.1.0 without replacing its storage or Runner. No external account, paid inference, deployment or publishing is authorized by this development task.

**Goal:** Implement persistent, approval-gated Campaign/ResearchRound decisions and durable, least-privilege coordinator wake-ups, with API/UI/CLI access and reproducible regression evidence.

**Architecture:** Reuse ResearchApp, Store transactions, immutable manifests, approval and attempt-budget services. Add campaign and wake-up records in the existing database. The scheduler reconciles authoritative state rather than assuming any one event is a complete result set. Browser code calls the same API as CLI and Pi tools.

**Tech stack:** Node.js >=22.16.0, TypeScript, SQLite, existing React workbench; pinned optional Pi 0.87.1. Real Pi requires Node >=22.19.0.

**Spec:** `docs/specs/` contains original uploaded designs; the full original-design M0–M9 scope remains authoritative and explicitly incomplete.

## Global constraints
- Pi remains the only agent execution kernel; no ORX runtime or fabricated AI fallback.
- No change to historical Run manifests, snapshots, raw evidence or results.
- A research decision approval never substitutes for approval of a concrete RunIntent.
- Worker termination does not cancel a formal Run. Stopping a Campaign stops new decisions/automation but still collects existing Run results.
- Old v0.1 records remain readable. New automatic-model behavior must not retroactively enable itself for old teams.
- Task-attempt credits are not provider billing guarantees. Unknown requests retain reservations.
- Do not bypass the managed browser policy; report browser QA and live Pi honestly.

## Review focus
1. Two completions arrive while root is busy: preserve both and deliver after user messages, without duplicate application.
2. Approval/goal/member set changes between proposal and apply: reject stale decisions, never silently override.
3. Incomplete/contradictory/corrupt metrics: retain observation and refuse promotion rather than invent scientific success.
4. Source retried/revised/stopped while a notification is queued or running: invalidate it and deny stale tools without affecting user prompts or external runs.
5. v0.1 restart/no dependencies/no credentials: old records remain accessible, unavailable features fail visibly and all core tests still run.
