# Batch 2C: project workspace snapshot to fixed research input

Baseline: `90aab4ff63f6659350cb35bed216d588d5b30b26`, batch 2B validated and pushed. Overall scope and routine commits/pushes are already approved. This batch implements one flow: project workspace text -> immutable snapshot -> existing artifact byte pages/real SDK ACK -> brief fixed input -> reopen. Draft, Run/archive/review, document parsing, GUI upload and model budgets remain later batches.

## Interfaces and semantic boundary

- Add `workspace_text_prepare` with `{path, purpose:'whole-text'|'dataset-reference'}` in the selected project/session context. It is a derived local READ, not a brief write or execution grant. Limit new preparation/selection to ordinary root coordinator sessions, retaining existing path exclusions, project/permission/lease/generation fences. Task/attempt/wakeup/native/approval/workflow continuation identities do not acquire this new capability implicitly.
- Return the existing ready fixed-text descriptor (`artifactId, sourceDigest, size, textSourceId, readProtocol:'fixed-text-v1', utf16Length, status:'ready'`) plus `sourceKind:'workspace-snapshot', workspace, path, purpose, workspaceBindingId`. The path/workspace describe the original acquisition, not a claim about the live file now. Preparation is explicitly O(N), bounded by the existing 120-second fixed preparation service deadline and a 20-second IPC margin for this new operation only; other budgets remain unchanged.
- A successful preparation selects a new immutable binding and distinct artifact identity even when CAS bytes deduplicate. Subsequent reads use the existing `artifact_read(fixed-text-v1)` and its exact SDK ACK; no second ACK transport or added page input field is needed. Coverage must match the binding's artifact/source and the ordinary root session identity. Preparing a source supplies no model-reading coverage.
- New fixed workspace inputs carry an explicit `sourceKind:'workspace-snapshot'` discriminator in `ResearchSourceInput` and its public schema. Their `readId` identifies their immutable binding, as attachment inputs already do. Do not invent a DocumentVersion or reinterpret existing fixed attachments/legacy InputRead records.
- Bind immutable session, anchor, original workspace/path, purpose, artifact/digest/size and textSourceId. A separate current selection follows only a fresh successful explicit preparation; cached replay and late ACK cannot switch it. Include accurate selection/binding/purpose/source in matching brief prepare/save fingerprints. With no workspace selections, preserve the old fingerprint representation. A new explicit selection may replace the same path in a new revision; previous revisions and delivered facts remain unchanged.
- The new branch freezes prepared snapshot bytes. A later live-path edit does not mutate or invalidate that snapshot; the caller explicitly prepares again to choose newer bytes. Legacy `workspace_read`/InputRead retains its existing live freshness and size/cursor behavior. New freeze boundaries still check current project/session/permission and snapshot authority/full SHA. Clarifying may skip an incomplete new choice; ready requires the selected purpose's actual coverage.

## Five acceptance conditions

1. A default-configured 512 MiB project UTF-8 file can be fixed and inspected with bounded I/O/memory; configuration exceedance, invalid encoding, exclusions, symlinks and path escapes fail without ready output. Empty text follows the explicit purpose semantics above.
2. Replacement, same-size overwrite, growth, cancellation, deadline or permission loss during acquisition/publication fails safely, retaining durable ownership and preserving shared CAS/history. A later live edit after successful preparation leaves the explicit snapshot intact.
3. Exact actual SDK ACK is required: whole-text gaps or merely reading nonempty EOF cannot ready a brief; dataset-reference can freeze after an inspected page plus full SHA. Pending/cache/transformed/late/foreign receipts cannot fill coverage or change current selection.
4. Brief preparation and save bind the same snapshot/purpose/selection. Re-preparation, old ACK and normal retry preserve old brief/evidence objects; reopen verifies the same original bytes and history. Reading/indexing does not grant brief writes, approval or execution.
5. Legacy workspace/attachment inputs, old cursors, bounded method parsing, backup/relocation/purge and protected origins remain valid. The new branch uses verified references without raising unrelated budgets.

One implementer; independent Astra/xhigh review of a frozen integrated snapshot. Root owns rulings, final validation and delivery. Do not modify the dirty main checkout, restart the main service, change layout, contact/rerun the completed benchmark chat, add dependencies or rewrite Git history.

## Necessary repair ruling after capacity verification

The first actual SDK512 run hit the 120-second preparation deadline. A read-only 100 MiB profile measured 16.55 seconds with 8,274 full checks taking 89.03% of time; repeated checks occurred during source acquisition, staged hashing, index building and CAS hashing. Keep the deadline. Check cheap deadline/cancellation every 64 KiB, full current authority and stable live path at actual 1 MiB source byte milestones (including short reads), and force full checks at source entry/open/EOF, after the entire prepared stage before intent, each permanent CAS link and complete CAS hash, ready/receipt transaction and return boundaries. Private staged source/index hash loops use the cheap budget; their combined prepared result cannot publish before the full current check. Split shared publisher critical checkpoints from hash-loop budget callbacks with the old callback as the default for existing callers. Do not infer critical phases from callback counts, weaken source identity/full SHA/publication ownership, or reduce old upload callers' checks. The catalog must explicitly allow either preparation operation's ready descriptor and preserve the workspace textSourceId for its input coverage.
