# 完全访问：持续任务、技术修复与恢复

用户于 2026-10-21 明确批准实施此前方案。范围是一条本地可信研究流程：开启新授权 → 提交本地实验 → 技术失败诊断 → 修复候选源码并验证 → 新实验 → 中断后核对原作业并继续。Pi 保持唯一执行内核，前端布局继续暂缓。

## 验收条件

1. 新授权可明确选择开发测试、实验、模型续接总次数及任务总时长无上限；旧授权及有限额配置保持原语义。用量、预留和 unknown 仍记账，不用 Infinity 或巨大整数代替无限。
2. 已确认终止且诊断可信的本地技术失败，纵使缺少科学指标，也能保存失败记录、创建绑定新源码摘要的修复候选，测试后提交新 Run。不得把失败结果标成完整科研证据，不修改冻结的原实验、方法、数据或指标契约。
3. 完成阶段会持久推进到下一项可执行动作；保留独立审查及正式整合/发布边界。没有新进展时不空转模型，不依赖每次人工发送“继续”。
4. 模型/宿主意外中断后，恢复同一任务的进度、已用额度及原作业；对已提交或启动不明的作业先对账，不重复提交，不按旧 PID 操作。恢复权限必须来自新授权的明确范围，宿主 Shell 权限保持重启失效。
5. 保留单次超时、资源/并发限制、撤权和未知状态屏障；暂停、取消、撤权分别处理。历史与已完成产物始终保留可读。

## 设计约束

复用 research-continuation、research-handoff、wakeup、准确批准、冻结源码与现有事务/执行 generation。持久任务及授权引用与临时 owner 租约分开，接管采用 CAS/fence。旧记录不静默升级、重写或刷新额度。恢复扫描与动作派发分开，归档既有事实不产生新的执行权限。

诊断证明由宿主核验退出、日志和 manifest/source 身份，科研完整性沿现有 verifier。修复只进入候选副本与新不可变快照；不扩大到任意根实验、远程资源或 Shell。对不支持计算 checkpoint 的已退出程序，仅能在核验和授权后建立新尝试，不能声称恢复内存状态。

无新依赖，不重启用户服务，不读取/复制真实研究数据库、凭据或原生对话。用户允许必要权限文案、API/CLI 接线；禁止布局重做。
