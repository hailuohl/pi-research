# Batch 2D: workspace delivery proof to ready research brief

Baseline: `aa79bb4557029936f0e77c376a4644a6789067b3`, batch 2C validated and pushed. One flow: ordinary coordinator reads a small project source and a legitimately managed session draft -> exact SDK delivery -> ready/confirm -> reopen/history. Large originals/datasets remain batch 2C fixed inputs. Keep generated-write/JSON/approval budgets; this batch does not add large draft adoption, historical draft raw-byte publication, a new preparation tool or a 512 MiB draft writer.

## Public contract

- Keep default `workspace_read({path,source?})` and its existing small complete-text response shape. It has no old cursor. For an eligible ordinary root project read, add optional `sourceInputReadId`; existing `draftReadId` remains for eligible managed session drafts. Both now identify pending observations, never immediate proof of SDK delivery. Owner reads continue to mint no agent evidence.
- Add an explicit branch `{path,source?,readProtocol:'workspace-text-v1',readBindingId?,cursor?,limit?}` for the same small-source/generated-draft budget. First call without binding starts at zero; subsequent calls must match the server binding's source/path/workspace. `source` still defaults to session. A binding cannot switch source or scope. Reuse the existing 4–16000 UTF-8 byte page limit, with BOM/CRLF/Unicode unchanged and complete-character boundaries.
- Page output keeps full-source `path,digest,size` and adds `readProtocol,cursorUnit:'utf8-byte',readBindingId,cursor,end,totalBytes,complete`, plus its applicable page receipt ID and managed `writeVersion` for drafts. `cursor` is actual start, `end` is the continuation position. Do not add redundant nextCursor/eof fields or reinterpret artifact/development/run cursors. The full digest/size cannot be replaced by page values.
- A binding may be the first receipt's ID, with `bindingId=id`; later pages reference it. No CAS or separate binding table is required. Each page binds the same full source tuple; use stable bounded current reads and full SHA under the existing small budget. This per-page O(N) verification is not a 512 MiB reader; project large originals use `workspace_text_prepare`/`artifact_read`.
- `research_brief_save.draftFiles` stays `{path,readId}`. Resolve the server binding and union only genuinely delivered matching ranges. Nonempty EOF alone cannot prove coverage; empty text requires an actually delivered EOF. Never combine different bindings or writeVersions.

## Delivery, selection and fresh acceptance

- Both default and page branches create new versioned pending rows in the existing draft/project read kinds. Capture original ordinary actor/generation, permission, call, full source tuple, byte range/content digest and first binding identity. Preserve old rows without pretending missing delivery means delivered. Reading does not create or reset a managed writeVersion.
- Extend the existing host `readResponse/completeReadDelivery` dispatch to workspace_read and its explicit draft/project token kind. Reuse the actual pinned SDK tool_execution_end result digest, one-time host offer, current worker/generation/permission/project epoch checks. Source services revalidate current bytes, managed writeVersion and page content. Task/attempt/wakeup/continuation/approval or workflow notice actors cannot mint or borrow ordinary root proofs. Existing exact approved-action recovery remains host-validated and can consume earlier genuinely delivered facts.
- Cache replay reauthorizes and verifies its original tuple without minting a new receipt/selection/coverage. Replaying an undelivered row poisons that row against a late ACK; already delivered facts remain. Reopen cannot recreate an old active host offer.
- Add a small persistent `research-input-selection` pointer (session/workspace/canonical path -> first binding ID, version), following existing selection patterns. Only fresh successful first reads move it; continuation pages, cache and ACK do not. Keep it across clarifying anchors. Clarifying skips incomplete new choices without freezing them; ready strictly requires complete delivered coverage. Include every effective active selection, including pending, in matching preview/save/approval fingerprints. A batch 2C fixed selection retains same-path priority; shadowed legacy reads cannot replace it. With no new legacy selections, preserve prior fingerprint representation.
- Do not let pending -> clarifying -> ready create source evidence, nor let a same-digest inherited input bypass a new pending choice. New delivered choices can reuse old artifact bytes, but a newly frozen reference must retain the new binding readId so its delivery fact remains traceable.
- Preserve current managed writes' complete declaration, live full SHA/size and writeVersion checks at new ready, approval preparation/decision/resume, confirm and fresh current capture. Same bytes written again still produce a new writeVersion and invalidate old proofs/approval. READ never grants ready writes, approval or execution. Owner manual ready may still omit draftFiles; explicitly supplied draftFiles must satisfy the same real proof rules.

## Historical acceptance boundary

- Never delete/rewrite historical receipts, brief payloads/digests or source bytes. An accepted-brief current-validation entry must load and validate the exact intact server-side ready/confirmed brief by ID/root, then inspect its exact frozen tuple. Do not expose client-controlled historical/accepted flags or accept arbitrary arrays as historical authority.
- An original stored ready/confirmed brief may retain its original legacy tuple for its own confirm/current capture and exact saved-operation replay. Fixed confirmed/development references remain independent of later live repairs. New ready draft proofs require actual delivery even if a legacy readId came from an older brief; an old pending approval has no accepted-brief exemption.
- Existing legacy sourceInputs already frozen into an intact server brief, including an old clarifying brief, may be inherited as old accepted facts without claiming SDK ACK. Old unfrozen InputRead rows cannot newly freeze or be mass-migrated into delivered selections. Current-anchor unaccepted legacy reads must require fresh reading; clarifying can skip them. New protocol rows still require their delivery contract in history validation.
- Keep Owner/manual omission behavior and existing metadata-only draft history. No new promise of historical draft text recovery.

## Bounded preimage refusal

New writes must not allocate an externally enlarged old file merely because the replacement text is small. Capture content preimages with stable reads under the existing content budget; metadata has its own existing budget. A stat-only guard leaves a growth race. Write-time unchanged checks and rollback/recovery target/backup comparisons must stream length/bytes against validated expectations rather than buffer enlarged live files. Preserve identity checks, conflict/journal retention and old journal formats; do not impose a new global cap on legacy journals or weaken recovery assertions. Existing JSON/base64 journal representation is unchanged, so this does not claim streaming parsing or a large draft recovery service.

## Five acceptance conditions

1. Legitimately workspace_write-created small drafts and legacy project sources reach ready/confirm via actual pinned SDK delivery, using default and multibyte byte-page modes; include empty/BOM/CRLF/emoji and coexistence with a 2C dataset-reference. Owner omission behavior and generation/JSON budgets remain.
2. Gap/EOF-only/pending/default direct-host calls/transformed results/cache/foreign or late ACK cannot create new acceptance. Pending project selection survives repeated clarifying and blocks ready until genuine reading completes; selection changes enter fingerprints.
3. Scope/notice/task/permission/epoch/path/workspace/encoding/live-change failures and same-byte new writeVersions reject stale proofs/approval. Oversized preimages and comparison growth races fail safely, preserving file/journal; old metadata budgets and recovery compatibility remain.
4. Original legacy accepted operations/history remain interpretable without fabricated ACK. Old unaccepted reads/new pending approvals cannot obtain historical exemptions; frozen old source references inherit exactly. Old confirmed references survive later repairs, and historical payload representation stays unchanged.
5. Reopen preserves delivered coverage and pending state without reviving host offers. Guarded small repair -> new version -> fresh read/ACK -> new ready succeeds, preserving prior revisions. No implicit approval/execution, large draft writer or Run/review completion claim.

One implementer, independent Astra/xhigh review, root final regression/clean build/critical SDK checks and explicit commit/push to the existing branch. Keep main checkout, live service, layout, dependencies and completed benchmark chat untouched.
