# 验收手册：研舟π五日产品改进

本手册用于未来产品实现验收，不是已执行测试报告。当前产品实施未开始。只记录真实命令、实际操作和真实结果。

## V-GATE：每批通用门槛

1. 开工前核对真实HEAD、分支、dirty改动、运行中的任务和适用AGENTS约束；不覆盖既有工作。
2. 先写能复现目标问题的定向测试，再做最小实现。
3. 定向检查通过后，沿真实UI/操作路径验证；组件stub或静态字符串断言不等于端到端通过。
4. 集成后执行与本批相关的单元/集成测试、类型检查和构建。确认dist对应当前源码。
5. 独立复核基于同一代码快照、实际差异和验证证据。修复后重验受影响部分。
6. 任务状态、验证状态、Git提交和远端同步分别记录；未运行/跳过不算通过。

## Day 1：基线与差距

- [ ] 核对HEAD、分支、dirty清单、暂存区、运行中进程和当前测试入口。
- [ ] 查明ResearchBrief、Task/Attempt/Run、验证、交接、权限与UI已有什么能力。
- [ ] 写出“已有 / 缺失 / 本轮改动”对照，避免重造现有系统。
- [ ] 固定一条用户流程与3–5条验收条件。

证据：真实git状态、当前代码路径、文件摘要、已有测试和基线结果。

## Day 2：任务摘要

- [ ] 显示真实目标、已确认范围、原任务标识、执行状态、产物、阻塞和下一步。
- [ ] 点击摘要能打开对应原始Task/Attempt/Run/operation，而不是复制状态。
- [ ] 旧项目与无Run研究任务仍可用。
- [ ] 列表/详情读取失败不显示成“没有任务”；unknown保持unknown。

反例：切换项目后旧请求迟到，不得将旧项目内容填入当前项目；无权访问对象不得泄露标题/摘要/数量。

## Day 3：验证证据

- [ ] 每项验证关联真实操作/命令、代码或输入快照、时间、退出码和真实统计（若有）。
- [ ] pass/fail/skip/not_run清晰区分，标明验证覆盖范围。
- [ ] 源码/输入快照变化后，旧证据标stale。
- [ ] 模型不能只凭自然语言把验证状态设为pass。
- [ ] 科学结果与工程测试状态分开显示。

反例：测试被跳过却报告通过；运行了旧快照的测试却将新源码标为已验证；命令返回非零但摘要称成功。

## Day 4：恢复与幂等

- [ ] 关闭会话后恢复原Task/Attempt/operation及已完成/未完成步骤。
- [ ] 断连/观察超时后先检查原操作，不启动替代副作用。
- [ ] 重试同一请求不会重复执行已完成的动作。
- [ ] 对一个失败/拒绝场景展示真实原因和安全下一步。
- [ ] 仅在当前证据确认R01/R02仍存在且阻断流程时，加入对应回归测试并修复。

反例：超时后原命令仍在运行，UI不能显示已失败并再次启动同一命令；重开后不能仅凭聊天摘要伪造完成状态。

## Day 5：集成与收口

- [ ] 完成真实端到端流程：输入目标→确认范围→执行→查看验证证据→关闭重开→继续。
- [ ] 至少一个失败/拒绝/unknown场景符合预期。
- [ ] 当前快照适用的定向/集成测试、类型检查和构建通过。
- [ ] 独立复核无阻断；未覆盖路径明确记录。
- [ ] 更新用户说明、STATE和HANDOFF，只提交本批文件。
