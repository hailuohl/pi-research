# Fixed-input development review

Create a new review with `development_review_prepare({jobId, readingProtocol:"fixed-obligations-v1"})`. The tested candidate, original confirmed brief, source identities and complete review obligations are fixed in the review and collaboration approval. Scientific profiles 1 and 2 retain their existing assessment, output and host-authority rules. Existing reviews cannot be upgraded in place; a conflicting protocol request fails with `DEVELOPMENT_REVIEW_PROTOCOL_CONFLICT`.

The development job still runs only its original small host-generated synthetic fixture. A large `dataset-reference` is a plan/review reference; it is not mounted, copied into candidate code or used for development fitting. This API does not enable large formal Runs, full-dataset scientific QA, large output artifacts or new backends.

New-protocol preparation supports at most 11 dataset references in one review: the existing per-area limit is 12 references, and `input_evidence` must reserve one for candidate code. More returns `DEVELOPMENT_REVIEW_REFERENCE_BUDGET` with `count`, `limit`, `referenceLimit` and `reservedCandidateReferences` before publishing review artifacts, wrappers, teams or approvals, including a confirm-mode session-action approval. The total source-input limit remains 32; old protocols and their reference budgets are unchanged. Dataset byte size is independent of this count limit.

`readingObligations` comes from the host, not the caller:

- `whole-text`: all required candidate code, protocol, brief, fixture, results and original required logs must have complete actual SDK-delivered coverage. An empty required target needs a delivered empty EOF read.
- `dataset-reference`: the exact source identity and complete SHA/size are verified, and the current independent reviewer must receive a nonempty bounded inspection and quote it in `input_evidence`. `inspectionSatisfied` remains separate from `readComplete`, which stays false for this obligation. Inspecting a page does not prove full-data QA or scientific validity.

For small whole-text artifacts, the existing `artifact_read` endpoint retains its UTF-16 endpoint cursor. Candidate reads retain `development_review_source_read` and its UTF-16 `end`. For a dataset or large approved log, use `artifact_text_prepare({artifactId,sourceDigest})`, then `artifact_read({artifactId,sourceDigest,textSourceId,readProtocol:"fixed-text-v1",cursor,limit})`; this cursor is a UTF-8 byte start, and `end` is the next cursor. The dataset may reuse its existing fixed `textSourceId`.

New reads return `reviewReadId` and `reviewReadingProtocol:"fixed-obligations-v1"`. They start pending and count only after the normal Host receives the exact SDK tool-result digest ACK. The new reading checks label normalized coverage ranges as `cursorUnit: utf16`; fixed-page receipts also bind their exact original UTF-8 byte start/end and source read protocol. No public “mark read” endpoint exists. Cached, truncated, transformed, failed, undelivered or other-attempt responses cannot supply coverage or quotes. Reference `{readId:reviewReadId,quote}` in the original five assessment areas and any required surface comparisons. Each dataset must have its own exact inspection reference in `input_evidence`; a wrapper, digest or list cannot replace it.

Permission revocation preserves the exact stored review, delivered reading facts and immutable semantic acceptance basis. Owner inspection still shows that history with `status: stale`; new reading, dispatch, active acceptance and adoption (`assertPassed`) require current permission. History is not a new access grant.

The large-read exception belongs only to the precise approved dataset target and current reviewer task. Native/private sources, PDF/PMC/source/discovery grants, origin restrictions and permission epochs remain enforced. Logs remain only the original job's exact stdout/stderr artifacts within its originally approved `logBytes`, at most 16 MiB. A dataset grant cannot enlarge a log grant. Closed paired profile success still requires empty stdout/stderr.

New dataset-aware development preparation action approvals include the precise confirmed brief and frozen source/fixture identities in a versioned internal fingerprint. Historical actions without this version retain their original fingerprint and approved execution semantics. Changing a pending action's brief while retaining the same code and fixture invalidates the new approval.

Validation entry: `node --max-old-space-size=192 scripts/verify-development-obligations.mjs --out=<temporary-evidence-directory>` runs a 3 MiB deterministic fixture through the actual pinned Docker backend and pinned SDK with a local provider. Root capacity validation can add `--bytes=536870912`. It requires the existing local Python digest and `desktop-linux`, never pulls images, checks the actual mounts and exact receipts, and retains isolated evidence outside Git. Its deterministic reviewer verifies transport and mechanical gates, not independent scientific judgment.

The new protocol separates current authority from full dataset integrity. Heartbeats, model-call guards, candidate reads, page authorization and SDK offer/ACK still recheck current identities, grants and immutable bindings, but do not repeatedly hash an unrelated dataset. Data pages authenticate their actual delivered blocks. A change outside a delivered block may remain invisible to that page; fresh complete verification at inspect, acceptance and adoption rejects it. `referenceVerified` is produced only by a full integrity inspection.

Preparation, worker dispatch before fork, acceptance and adoption retain complete SHA/size and archive/method validation. A host-only synchronous boundary context removes duplicate scans of the same source within that boundary. It is not a model/transport argument, cannot survive the callback or cross await/RPC, and is discarded after the call; later calls perform a new full verification. Current authority is rechecked before committing or spawning. Existing protocols and callers without a context retain the original full validators.

Artifact text preparation also reuses an existing workspace text source for the exact same project/artifact ID/digest/size after checking source/index integrity and index origin. It preserves the original textSourceId and does not recreate the source or index. An index with matching bytes alone grants no access. The30-second worker lease, RPC limits and resource budgets are unchanged.
