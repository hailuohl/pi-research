# v0.2 持续研究与结果唤醒

这是原设计 M5 的受控本地增量，不是全量自动科研或真实 Pi 能力认证。

## 数据与执行边界

`Campaign` 保存研究目标、共同运行契约、主模型、预算和边界；`ResearchRound` 保存同一轮共同父实验；`CampaignMember` 绑定固定 `RunIntent`；`RunObservation` 保存终态实际观测及原始指标证据；`CampaignDecision` 保存有版本约束的决定；`Wakeup` 保存主会话的待处理通知。

继续使用唯一 `ResearchApp`、SQLite 事务、Run/Evidence/Approval/Session 与独立 Runner。所有研究活动共用现有执行内核、实验记录和持久化队列。

`Campaign.state=stopped` 表示不再新增研究决策与自动分析。当前轮次关闭表示停止分配，不表示它的全部计算成功。已经存在的 Run 仍受监管且继续采集结果。只取消指定 Run 才请求停止正式计算。

## 观测与决定

调度循环重读所有已登记成员对应的终态 Run，以 `(campaignId,runId)` 内容地址建立一次观察。即使事件游标丢失、浏览器断开或服务重启，也通过权威数据库恢复；事件只是通知，不是完整结果集。`unknown` 的外部状态不被当成失败或成功。

完整成功观测需要验证 RunManifest/契约摘要、产物内容摘要、metrics.json 原始内容与数据库指标一致、指标定义与有限数值、证据归属。校验仅说明产品数据一致，不能证明科研解释正确。缺失和无效结果不会补造指标。

四类决定先提出，再单独批准并应用：

| 决定 | 本版语义 |
|---|---|
| Repair | 只给尚未回答问题的临时节点一次有界重新登记授权；不自动生成修复代码，不自动重跑 |
| Refill | 同一父实验下新增兄弟候选，固定快照并准备独立 RunIntent；不自动批准正式计算 |
| Promote | 必需成员均已终态并观察后，将指定已测量冻结节点作为下一轮父实验；可准备下轮候选 |
| Stop | 停止新增决策/分析，保存原因和结果；不取消已有正式 Run |

决定审批绑定成员、原始运行状态、输入摘要、活动版本、模型与候选配置。之后加入成员、取得新结果、改变活动版本等，可能使旧决定批准失效，需要重新提案。应用过的决定幂等返回原 effects；不能重复派生。遇到基础设施失败不能以自动重试绕过 Repair 次数。达到连续退步上限时，不创建新一轮候选。

## 唤醒与权限

团队完整或部分结束时可产生综合通知；活动每个新观察可产生分析通知。API 的 `autoSummarize` 和 `autoAnalyze` 默认 false，旧记录没有该字段也不自动授权。UI 新团队有明确自动综合复选框，批准文本包含该行为；活动自动分析默认不勾选。

通知持久化状态：`pending → queued → running → completed/failed`，另有 `cancelled/superseded`。模型不可用时只保存阻塞原因，不创建虚假助手回复、会话请求或扣除尝试。

自动输入以 `role=system, origin=automation, wakeupId` 保存，不冒充用户亲自发送的消息。主会话忙或有用户消息时等待；用户在自动分析期间发送的 steer/follow_up 留待分析结束，避免混用权限。该行为与交互式主会话的即时 steer 有明确差异。

自动执行只开放获分配运行/证据/任务读取、草稿产物和待批准的活动决定提案。禁止正式执行、批准、工作区访问、递归委派与发布。所有工具再次校验会话租约、通知来源版本、活动状态和资源范围。取消或过期立即撤销这些能力，不等待模型自觉停止。

Worker 的 settled/done 不等于业务成功：没有可展示分析文本时通知失败，不展示成综合完成。真实 Pi SDK 未在本环境安装；IPC 测试使用显式 fixture worker，只验证宿主进程协议和状态机，不证明模型输出质量。

## 配额与恢复

额度单位是 `agent-attempt`，不是 token 或货币。一个受控分析尝试可包含多轮模型/工具调用；当前 Worker 限制最多12轮、40次工具、宿主300秒运行窗口，供应商实际收费仍需核验。整个本地宿主最多2个模型 Worker，团队设置不会突破该上限。

自动综合的团队保留至少一次可用尝试，失败重试不得花掉最后这份额度。暂停尚未启动的通知释放预留，恢复时使用递增的 queueGeneration 重新预留，不能复用已结算 reservation。运行中故障按未知额度保留，不自动释放后无限重试；通知最多2次尝试，重试需用户明确操作。

暂停通知、取消消息和关闭活动时，清理空的主会话队列；已有用户消息不删除。服务重启后的未知模型调用不会自动重发。旧 Lease 不能再提交副作用。

## 已知边界

固定执行器目前仅随包受信数值程序真实验收；Docker与全部远程执行器仍有缺口。没有有限批次的自动 Run 批准策略、自动任务重规划、全量数据目录迁移、模型账单硬上限或自驱动科研效果评测。对历史旧记录的兼容验证不代表可在两版本服务同时写入时升级。
