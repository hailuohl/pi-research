# 从 v0.1.0 升级到 v0.2.0

本版继续使用通用records表和schema_migrations版本1，新增业务对象类型，不批量改写已有实验、Run、Session和产物。验证范围是原绝对数据目录不变，旧服务停机后由新版本接管；不支持同时运行两个版本的写入服务。

## 推荐操作

1. 等待旧版正式Run达到终态，处理所有unknown记录；停止Agent和控制服务，确认没有遗留Runner写入。不要仅关闭浏览器就升级。
2. 在所有写入停止后，备份**整个**原数据目录。包括数据库及WAL相关文件、项目、快照、Run、证据、Session和访问令牌，不能只备份state.db。妥善保管备份，不上传凭据。
3. 把v0.2解压到新的程序目录。不要移动原数据目录；旧记录包含绝对路径。
4. 在新程序的`.env`中设置原数据目录绝对路径，例如：

```dotenv
PI_DATA_DIR=D:/Research/pi-research-v0.1/pi-research/.pi-research
PORT=4317
```

Linux/WSL使用原系统路径，如`/home/user/pi-data`。跨Windows/WSL的路径转换不是已验证迁移，不要直接替换斜杠就认为兼容。

5. 原Pi运行时位于旧程序`.pi-runtime`，不会因为指定数据目录就自动搬移；在新程序按README安装固定版本运行时，妥善迁移自己必要的模型配置/凭据。未配置模型不影响读取实验与使用本地示例。
6. 进入新目录运行：

```bash
node dist/apps/cli/index.js doctor
node dist/apps/server/index.js
```

确认doctor显示的数据目录正确，再打开终端地址。核对旧项目、实验快照、Run指标、报告和证据；新建研究活动不会自动重跑旧实验。

## 回退边界

发生异常时停止新版全部写入，再使用此前完整备份恢复旧数据，并用旧程序启动。不要让旧程序继续写已被新版新增Campaign/Wakeup对象的数据；旧调度器不理解这些对象。新版本产生的实验与会话不会自动合并回旧备份，需要单独导出保留。

## 已执行兼容验证

`scripts/verify-legacy-upgrade.mjs <已解压的可信v0.1.0程序目录>` 会**新建一次性测试数据目录**：用旧版CLI真实运行4个数值实验，使用新版读取同一路径，建立新活动并登记一个旧Run，验证原4个Run内容摘要和报告字节未变化、没有额外提交Run且没有模型调用。不会使用已有个人工作数据。

命令结果随包保存在`docs/acceptance/upgrade.json`。它只覆盖该受控兼容案例，不代表全量用户数据、操作系统差异、整机迁移或在线升级已验证。
