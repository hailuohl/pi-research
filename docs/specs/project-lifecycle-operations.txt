项目归档、回收站与离线永久清理

入口：左侧“项目管理”。

归档
活动项目可以归档。归档后从活动列表隐藏，原会话、固定源码和已有成果保留为只读。
取消归档保留项目 ID 和历史，不重新启用旧审批、授权、排队请求或自动通知。
有未结束的执行、排队任务、未知结果或恢复占用时，先通过原工作流核对或结束，再重试。

回收站
活动或归档项目均可以移入回收站。普通链接、下载、历史请求回放及事件入口停止返回其研究内容。
回收站仅显示名称、ID、删除时间及原状态。还原恢复为删除前的活动或归档状态。
文件不移动或清除；回收站不自动清空。旧授权不会因还原恢复，固定来源绑定的旧会话保留历史。

永久清理
仅回收站项目可以请求永久删除，须核对完整 ID 并输入准确项目名称。
请求后项目进入待离线清理状态，不能再还原；请求成功不代表文件已经清完。
先完成或停止同一数据目录的任务，并退出控制服务、Worker 和其他打开该目录的命令行进程。
数据库连接关闭而进程仍存活不等于离线。系统不会自动杀进程、强制解锁或启动恢复作业。
首次升级维护协议时，所有旧版本写入进程也须退出；旧程序不受新登记协议保护。

在项目代码目录运行（项目管理中的状态页提供准确参数及可复制的 PowerShell 示例）：
  node dist/apps/cli/index.js project purge --project <项目ID> --data <数据目录> --offline --confirm-name <准确名称>
若已开始、失败或异常退出，续用同一个请求及固定计划：
  node dist/apps/cli/index.js project purge --project <项目ID> --data <数据目录> --offline --confirm-name <准确名称> --resume
仅查询状态：
  node dist/apps/cli/index.js project purge-status --project <项目ID> --data <数据目录>

维护会核对进程、未完成执行和受管资源，然后保存清理计划与进度，再删除计划内文件和记录。
清理进程硬退出时，门禁保留，普通程序不能自行恢复写入；显式续清须先证明原维护进程退出。
同步失败会保留待续清状态和计划。只有最后核对完成后才显示完成，并保留最小完成回执。
新服务重新打开后，可以在项目管理中查看上次清理状态；普通项目入口不再提供该项目。

保留边界
不清理导入原目录、GitHub 或其他外部目标、独立备份、其他项目、个人模板、全局配置和共享凭据。
共享对象仍被其他项目或全局材料引用时保留；仅明确属于目标项目且没有其他引用的对象可以回收。
无法证明归属的旧回执、无引用缓存、临时准备文件或未支持的存储结构会在删除前阻断；不能猜测删除。
该流程清理当前受管数据集，不承诺磁盘介质级安全擦除，也不会改写已创建的外部副本或备份。
