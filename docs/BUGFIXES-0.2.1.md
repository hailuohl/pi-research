## 本轮额外流程问题

部分成果现在明确阻塞，并可在限额内请求新尝试；其历史提交不会被覆盖。无法完整提交的上游也会阻塞审查任务，不再留下一条永远 active 的等待链。

新提案只接受规范相对路径，并在最终复制时再次核对批准的每个文件摘要。相同基础已变化、任务验收已变化、产物摘要已变化或批准内容被篡改时拒绝应用。整合是创建新子实验，不是Git合并或修改父节点。

实验总览使用契约中的指标和方向，不再把所有研究显示为MSE。条形长度仅表示绝对值，并明确不等同于科研优劣结论。复杂多指标/置信区间可视化仍待实现。

## 代码交接的实际边界

用户/交互式主协调者指定父实验和文件映射 → 准备固定候选 → 展示前后文本 → 人工批准 → 创建新子实验 → 再准备与批准Run。任务产物必须是当前已验收结果所明确交付的文件，不能捡用未审查的旧草稿。

本版本接受最多50个变更、每个新文本文件2MiB、整体快照64MiB；支持明确新增/替换/删除。UI提供一个文件的表单，多文件走同一API。没有自动Git整合、开发沙箱测试或远程发布；`testsStatus=not_run`，绝不表示测试已通过。任意代码仍需要未实测的Docker路径，宿主只运行固定受信示例。

## 研究结果语义

answerDisposition（是否回答问题）、进程state、产物integrity、科研judgment互相独立。有数值的失败仍保护代码；无数值的OOM/NaN类记录需用户基于真实日志判断。人工确认answered不会凭空生成数值，也不会自动把假设判成supported。人工确认unanswered不会把failed改成succeeded。
