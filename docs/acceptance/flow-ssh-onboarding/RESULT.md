# SSH 首次确认与自动环境准备

日期：2026-10-08。基线：3ba320e53f69a30eb4edfb287a0aafe7f3fc3d94。

连接器保留三个板块。新建/编辑 SSH 不再要求用户准备 known_hosts；先获取一个规范公钥及 SHA256 指纹，用户核对后确认，应用保存不可变版本的主机记录。挑战绑定完整配置、身份摘要、目标版本及五分钟有效期；未确认只做公钥扫描，不认证或执行远端命令。已信任地址主机 key 变化不自动接受。

确认后以严格主机校验登录，检查固定监管器和私有工作目录。仅缺失时安装仓库原字节；已有文件不覆盖、不修改已有目录权限。安装需要 root 或免交互 sudo，Python3/Linux 不具备时提示。Docker 缺失只提示安装，已安装但服务/权限不可用单独说明，只有取得有效 Linux 引擎身份才显示当前已连接。页面活跃时每20秒串行只读检测已确认的 managed 连接；不开新常驻监控、不重复安装、不自动运行 GPU 容器。

## 验收结果

1. 指纹确认、过期/版本/身份变化拒绝、错指纹无登录/安装及严格主机校验由相关服务回归覆盖；真实回环独立服务器公钥指纹与 challenge 一致，挑战前/后及错指纹后用直接 exec test ! -e 退出码核验监管器仍不存在。
2. 两个新的一次性 Linux SSH 容器验证正确确认后固定 helper 和私有 workspace 创建。固定 helper SHA 与仓库相同；重复准备及只读检查没有改变其 inode/mtime。真实 Docker 缺失、Docker CLI 存在但 daemon 不可访问，以及启动独立 DinD vfs 引擎29.8.1/Linux 后 ready 均实际区分。
3. 浏览器实际展示新表单、目标/指纹和未勾选时禁止确认；390×844无水平溢出，没有known_hosts输入。真实回环卡片显示监管器/SSH Docker状态；后台只读检测及失败+503、pending和TTL的旧信息撤销由UI回归覆盖。
4. 安装 reservation 与新 Run 双向互斥，安装每次网络步骤前检查队列/配置/token/租约；旧已启动 handle 的对账与冻结源码、审批保持。未知安装需只读核对，不能通过备份丢失私有目标后留下不可恢复的锁。
5. legacy手动配置/CLI保留；主Agent仅获安全状态，三个新管理操作仍user-only。私有挑战及managed主机记录排除科研备份，不上传Git；FS与SQLite不宣称全原子，落盘失败回归证明重新打开可见并可显式对账恢复。
