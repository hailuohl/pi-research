# Pi 模型 HTTP 请求排队

资源页现在可单独设置共享模型 HTTP 上限、暂停新外发，并查看等待、执行、未知占用和历史回执。Worker数、HTTP请求数、计算配额分别计量。额度跨控制器原子分配，流式正文结束才释放；未知状态不自动当空闲，旧版未受管Worker存活时阻止新派发。

真实智谱 `zai-coding-cn / glm-5.3` 两会话同时存活：HTTP上限0时两项等待，开放1个槽位后依次完成，两次均200。第二次在第一次正文结束90毫秒后取得额度，无重叠、无重试；两会话正常idle。浏览器设置、等待/执行状态、刷新保留和390px入口均通过。本批未启动Docker或新增科研产物。

独立复核发现并修复了取消时截断正文误报成功、任务取消与额度派发之间的竞态。688条旧记录中的业务记录及15份旧原生会话文件保持不变。原生历史和日志留在验收库，只交付[一份机器证据](evidence.json)。

当前控制固定SDK中四类可注入fetch的API，并强制HTTP/SSE；其他传输明确失败，不能绕过限流。实际只验收上述智谱模型；HTTP连接结束不证明远端生成已停止，也不是Token或账单上限。远程后端、更多目标、完整性能/迁移分发及PR01–14其余范围继续。

集中验证：734项，712通过、0失败、22跳过；干净安装/构建/类型检查成功，430个文件完全一致。独立复核无剩余阻断。
