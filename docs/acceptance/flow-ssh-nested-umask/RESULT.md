# 限制性 umask 下的 SSH 嵌套源码 Run

SSH→远端 Docker 现可在远端 `umask 077` 下运行多级、隐藏路径的固定源码。旧协议在真实 Linux 权限夹具中把嵌套目录建成 `0700`，测试先失败；修正后逐级确认目录并设为 `0755`，job 根仍为 `0700`、记录为 `0600`、源码为 `0444`。真实回环 Run `7cb63e83-bfa1-4af2-8c05-9340c8578798` 经原 RunIntent 单独批准，非特权 UID 65534 的禁网、只读根容器读取嵌套源码并生成 6 项已核摘要产物，状态 `succeeded / complete / exitCode 0`；`start-events.txt` 只有一次启动。指标 `mean=2` 仅是固定三点的软件验收，不是科研结论。

新目标别名重新 probe 后，旧成功 Run 仍可用原 handle、原协议摘要只读取得 `status/result`，本地旧记录与 6 项旧产物原摘要保持。协议兼容仅开放**原身份匹配的终态**读取；活动、未知、取消或新的提交不能沿用旧协议。新 Run 终态后关闭/重开控制器仍回查同一 ID 和容器，**未实测本批运行中重启**；此前 SSH 批次的运行中恢复证据保持。隔离回环主机已还原为停止状态。没有外部授权主机，Slurm 与真实远端 live 项仍未验证。

本批前端不验，原始日志、SSH 私钥、测试数据库和容器状态留本机忽略目录；必要 ID、摘要、权限与验证结果见 [evidence.json](evidence.json)。全量回归 852 通过、0 失败、23 项环境可选检查跳过（含 Windows 上 POSIX 权限测试）；干净构建一致，独立复核发现的旧终态回查阻断已修复并定向复核通过。
