# 固定文稿进入报告与离线成果包

本批接通“选择固定文稿构建→生成报告→回查图形来源→离线交付”。报告可只包含文稿，也可组合既有 Run/已采纳结论；旧报告保持兼容。编译、图形和实测数据沿用已有真实产物，本批没有新模型调用或重新编译。

## 可用流程与实物

在 **报告与成果** 页选择成功、完整且来源有效的构建，点击“纳入此固定构建”，再生成固定报告。最多选择 20 个构建。报告保存所选文稿修订、源文件、PDF、编译清单、镜像/脚本/依赖及批准身份，不跟随最新版本变化。历史报告可精确返回原 revision/job 和 PDF 预览。

## 来源失效与兼容

独立审查发现并关闭一个 P2：替换编译作业的批准记录后，报告原先仍可沿用旧批准身份。现在核对报告冻结的批准 ID；替换或撤销后旧报告失效，新导出被阻止，历史引用仍保留原批准身份。Sandbox 同类替换由文稿资产中的冻结批准链阻断，已补回归。

浏览器验收另发现历史 CSV 被归档为 `application/octet-stream`，导致纯文本预览被拒。修复只对固定绑定中扩展名为 CSV/TSV 的这类文件，经原摘要、NUL 和严格 UTF-8 检查后提供有界文本预览；不改原产物媒体类型或字节。PNG/PDF、未知二进制及不合法文本仍拒绝作为文本预览。修复后的 21 行原 CSV 已在浏览器复验。

在另一个独立副本中撤销最终构建批准后，报告显示 APPROVAL_STALE，新报告和新导出拒绝，历史正文及 CSV 仍可读。该副本仅一条批准记录改变，主验收副本的 **95 条当时记录**保持不变；主验收副本中的 **91 条原记录**也与上批数据库逐条字节一致。见[撤销证据](revocation-evidence.json)。

旧真实 Run 报告 `28b4360a…` 在独立备份上仍为 verified/current，正文摘要和固定 `main.py` 一致，原 MSE **0.000050345031695457565** 与指标引用保持不变；**173 条旧记录**全部保持原字节。它与当前文稿属于不同项目，仅用于兼容验收，未伪造跨项目来源。见[旧报告兼容](old-report-compat.json)。
