## 实际变更

- 已导入的流式文本/数据原件可沿普通 coordinator 消息附件绑定；新 `fixed-text-v1` 明确原件 SHA256、用途及 UTF-8 字节游标，正文每页最多 16000 bytes。
- pending 读取回执只有通过准确 SDK 结果摘要、调用、会话、代际、权限与当前来源确认才 delivered；EOF 不代表前面已读，缓存不制造送达事实。
- whole-text 要求完整覆盖；dataset-reference 要求实际检查页和宿主全源 SHA256，复用原 artifact/CAS，不把数据集全文放进模型或另复制一份。
- binding、历史回执与旧简报不可变；当前选择独立管理，正常重附加、失败重试和显式用途切换可使用新绑定。澄清保存可跳过尚未满足覆盖的新选择，ready 严格检查；准备审批与保存采用相同状态和选择指纹。
- 只读分类保持：可读取和记录事实，不因此获得简报写入、审批或执行权限。旧 UTF-16/BOM、原生媒体与 JSON 上传语义保持。

API 说明见 `docs/api/fixed-attachment-inputs.md`。

## 五项验收

1. 配置范围内 512 MiB 原件可附加与受控分页，旧 JSON/原生限制独立且能力元数据不误导旧客户端。
2. 页 I/O、内存、原文与摘要有界且准确，逐次检验项目/会话/消息/来源，拒绝损坏和越权。
3. 只有真实成功 SDK 送达计入读取范围，失败、转形、截断、迟到、缓存及覆盖缺口不能伪造完整阅读。
4. 用途明确进入研究输入与审批指纹；whole-text 和 dataset-reference 不混淆，旧历史不被改写。
5. 冻结与复验采用固定引用、流式校验和按需方法来源加载；撤权、重开、备份恢复和重试保持正确。
