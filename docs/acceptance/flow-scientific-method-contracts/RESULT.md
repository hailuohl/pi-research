# 科研方法合同与真实 Pi 验收

本记录覆盖 DOI/研究身份混淆、协议与执行判据不一致两项阻断，以及同一真实任务暴露的报告审查缺口。本批限定流程已通过独立代码与科学验收；接纳对象是修订后的报告，旧 disputed 与此前失败记录保留，不把机械通过当作科学正确。

## 实际修复

- **DOI只关联候选报告。** 从实际读取并冻结的来源构建账本；同 DOI 不推断同一研究，重复记录身份仍保留。`studyIdentity=unknown`、`totalStudies=null` 表示未知，不是零研究。
- **协议和执行共用冻结规则。** 结构化合同生成完整协议、边界案例与开发/正式判定；宿主从实际逐行预测见证重算 RMSE 增益、标准误和同单位区间。精度门槛、来源摘要、夹具身份和归档重开均受校验。
- **限制重复错误出口。** 宿主独立合成夹具；候选成功输出仅允许三份闭合 JSON，成功日志为空。协议、账本、事实、判定和预测 CSV 由宿主归档。保留旧编译版本与技能发布包。
- **正式报告绑定完整材料。** 专用入口固定报告、全部 Run 源码/输入/归档及空日志，生成有边界的数据质量事实；接受前要求当前尝试的真实全文读取和准确引文。机械完成、原生意见和科学采纳分别记录。
- **错误路由在写入前拒绝。** 对“同主会话的一份 Markdown＋一个成功完整的配对 Run”的单 reviewer 新计划，运行时要求使用正式入口；不按正文猜意图，不自动扩权或批准。一次审查只给一次尝试，其他协作与历史计划保持原样。

原问题不是简单的正文漏送：读取只能证明材料送达，不能证明 DOI 推断、统计量和自由文字解释正确。此次改动落在数据契约、共享计算、输入范围和实际读取校验上。

## 同一真实研究的结果

Pi SDK 0.87.1，`zai-coding-cn / glm-5.3 / low`。固定公开红酒数据、模型和划分不变；实际两个开发作业（首个失败、第二个通过），一个正式 Run。

- 正式 Run：`7520d5f7-e552-4981-a849-e49259a88a1f`，成功且归档完整。1599 行按完整记录去重为 1359 行，训练 951、测试 408。
- RMSE：线性 0.7208234711，二次 0.7197221489；增益 0.0011013222，95% 配对区间约 `[-0.000575614, 0.002778258]`。冻结的 0.02 操作判据下结论为 **inconclusive**，不是等效或无效应证明。独立 60 位十进制复算与实际见证一致。
- 原报告错误地称 quality 有非整数值，旧通用审查给过 accept。该历史意见保留，未追认为科学通过。
- 修复后，Pi 实际遇到运行时拒绝，自行切换专用入口。新 reviewer 在同一 low 档、一次尝试中读完 **31/31** 项材料，留下 **47** 份可对应原生调用的凭据，自行发现 quality 全为整数并提交 **disputed**。
- 原生产会话实际收到宿主投递的完整终态 summary，据此保存修订版，并从头回读全部 **5341 字符 / 10208 字节**；未新增拟合、种子、正式 Run 或审查尝试。它没有另外用工具读取五区 assessment，不能把 summary 投递写成该操作。
- 修订报告：`1a6dacb3-4c0c-451b-9ecc-5304a45fc6f2`，SHA256 `4293cde5f1c28ce760ad87adf0e0a8dfe0d9125f5ebaf54932f8474d6f3c1e91`。原错误报告保留。

## 介入与适用边界

- 本轮没有向 Pi 提供外部科学错误位置、纠正答案或提高档位。操作者进行了精确审批、一次新审查流程澄清、维护/完成通知；更早的源码整合由 owner 按已审字节补齐，旧通用报告审查也曾人工补上下文。因此不称全过程完全自主。
- 原八方法正文实测覆盖为 **6/8**，未观测 hypothesis-generation 与 experimental-design 正文成功交付；本批不冒称 8/8。原 root 保留历史技能 pin，新任务正常使用新发布包。

- 非阻断 MC-N1（v4 单独 protocolDocument/roles 元数据转发）保留；现有完整协议字节、唯一角色与固定材料检查仍生效。
