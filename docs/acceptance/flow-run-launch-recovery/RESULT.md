# Run 启动失败恢复（2026-10-22）

范围：仅修复原 queued Run 在监管进程启动准备失败后不能再次调度的问题。

验收条件：

1. 控制目录受阻或日志打开失败，修复路径后同一服务可再次调度原 Run。
2. 同步 spawn 失败同样可重试；正常启动继续保留重复启动保护。
3. 失败记录为 run.launch_failed 事件（错误码、Run ID、retryable），Run 状态、批准快照和历史不改写。
4. 原 Run 可实际完成内置信任示例，重开后仍可读取终态与失败事件。

实现：扩大 launchPending 的异常清理范围，保留原文件描述符释放和正常启动保护；异常继续交原调用方处理。

验证：

- 修复前三个回归场景均因原 Run 不再获得调度而失败。
- 新回归及既有调度/计算队列检查：25 通过，0 失败/跳过。
- 既有 runner 集成：9 通过，0 失败/跳过。
- 真实内置信任示例：路径受阻 → 移除 → 原 Run succeeded/complete → 重开保留结果及单条 EEXIST 失败事件。
- 全量回归、干净构建和独立复核：最终状态见 evidence.json。
