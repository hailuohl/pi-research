# 受控文本写入的崩溃恢复

项目、私有会话与实验的现有受控文本写入现在保存持久恢复记录。新启动的控制器或 CLI 在数据库写锁内对账：未提交写入恢复原文，已提交写入仅清理残留；重复恢复不增加业务记录。无需新增审批或权限。

真实 Windows 子进程在提交前、提交后分别被父进程强制结束，重开结果符合预期。外部修改触发 `TEXT_WRITE_RECOVERY_CONFLICT`，原文恢复材料与外部内容保留；受影响工作区不能读取、快照或继续写入，其他工作区与历史可读。独立夹具中保留外部副本、恢复原文后，重开成功解除隔离。请勿直接删除冲突标记或恢复材料。

已有审批与固定快照保持不变；真实旧数据库的只读备份升级至 schema 8，709 条记录逐字节不变。owner CLI 的正常写入、原幂等键重放及变更输入拒绝均通过。原服务、模型和作业未重启，本批无新 Pi、Docker 或浏览器任务。

范围与限制：仅覆盖传入 Store 的受控文本写入；目录替换和其他文件系统事务继续保留。恢复依赖支持硬链接的同一文件系统，本机 Windows 路径已验；不宣称断电或其他文件系统已验。旧控制器进程不会热更新，使用此保护需要后续在无在途任务时更新控制器，不能混用旧控制器推断恢复安全。前端布局的 5 个源/生成文件改动保留未提交。

集中全量 755 项：733 通过、0 失败、22 跳过。独立复核发现摘要校验与辅助层重读间的竞态，文本及 Windows 模式元数据均已修复并定向复核关闭；最终相关检查 13 通过、1 平台跳过，实际恢复路径重验通过。必要修复后的最终干净安装、构建和类型检查成功，441 个工作区构建文件一致；其中 3 个暂缓布局产物保留原提交版本，不进入本批提交。

[机器证据](evidence.json)记录终止边界、摘要、历史保留及检查结果。原始日志和夹具留在本地 `.validation/text-write-recovery-flow/`，没有复制原会话、源码或截图。原 PR01–14、目录恢复、迁移/备份与远端等未完成范围继续保留。
