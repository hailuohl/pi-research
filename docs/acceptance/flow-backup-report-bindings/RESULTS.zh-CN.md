# 含固定图形来源的研究库：离线备份与隔离恢复

当前 Wine 研究库现在可以走通既有 **离线备份 → 校验 → 隔离异址恢复** CLI 流程。此前备份器把报告中有意省略宿主路径的图形输入绑定当作路径型执行输入，返回 `BACKUP_REFERENCE_INVALID`。修复只在 `report.bindings.figureSources[].dataArtifacts[]` 按固定 ID 回查同项目 artifact，并核对 SQL/记录项目身份、摘要、大小和实体字节；执行清单仍须提供原路径，历史报告与批准不重写。

停止已确认空闲的原控制服务后，对真实累积库创建并校验了 **328 文件、18,226,472 字节**的备份，再恢复到独立目录。恢复副本保持离线；它与原库的 **332 条记录摘要完全相同**，112 个 artifact 均通过实体摘要核对，令牌与模型配置未打包。原服务已在同一端口和令牌下恢复，活动 worker 为 0；旧 Run、报告、PDF、检索历史和批准身份保留。备份与恢复副本仅留本机，不进入 Git。

修复回归先在旧代码下复现合法报告备份失败；独立复核又发现嵌套数组可能绕过执行输入路径检查，新增用例先失败，随后补明确拒绝。全量回归 **761 通过、0 失败、22 跳过**；窄修复后备份/迁移相关 **10 项通过**，最终隔离干净构建 **450 文件一致**，独立数据保留复核无剩余阻断。原始日志只留 `.validation/flow-backup-report-bindings/`，必要身份、摘要及验证结果见[机器证据](evidence.json)。本批未重跑 Pi、Docker 或浏览器。

其余 PR01–14 缺口继续按计划逐批推进；本次恢复副本只是离线验证，不作为第二个活动控制器。
