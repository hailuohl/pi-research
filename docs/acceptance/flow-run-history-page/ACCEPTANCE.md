# 本批验收：Run 历史按稳定游标分页

范围：为已保存的正式 Run 增加 owner-only 后端 `run_list` 操作，使用有界、稳定的 SQLite 行游标，返回可选择的运行摘要，再沿用 `run_inspect` 读取单项完整结果。不改现有 `/projects/:id` 响应或前端，不启动 Pi、Docker、SSH 或新 Run。

1. **成功路径。** Owner 对确切项目按 `cursor`/`limit` 读取 Run 摘要页；每条含 Run/Experiment ID、状态、完整性、科研判断、时间和已记录指标。以返回的 Run ID 调用原 `run_inspect`，取得同一持久记录及产物来源。响应最多给定上限，不扫描并返回全部 Run。
2. **边界与失败。** 非 owner、跨项目访问、非法/过大游标或页大小在读取前拒绝；摘要不带工作目录、私密目标配置或原生对话。读取不写数据库、不派发工作、也不把成功状态当科研结论。
3. **游标语义。** 在已返回第一页后，新 Run 插入或旧 Run 状态更新不改变已见条目的顺序；后页不重不漏，末页明确结束。现有记录和审批/RunGrant 绑定不被改写。
4. **刷新与验证。** 关闭重开后以同一游标继续得到原 ID 与当前真实状态，既有 Run/Artifact 字节不变。开发只跑相关检查，集成后一次全量回归、干净构建和独立常规复核；本批后端 HTTP 只验关键路径，前端不验。
