# NVIDIA：本地、Docker、SSH 执行

2026-10-07；基线 `8aa1f25dbacb29efb7e05f6f64a59577186abc5e`。用户已明确首期只支持 NVIDIA；其他电脑保留本地 CPU、Docker、SSH。前端只增加运行环境与 GPU 的必要配置/状态，不重做布局，不恢复其他执行后端。

## 验收条件

1. Windows、macOS、Linux 使用各自电脑配置的运行环境，避免开发机路径、账号或显卡编号硬编码。新增 `local` 正式运行，保留原 `trusted-example` 固定示例及历史。本地 CPU 不依赖 GPU 驱动或 Python；NVIDIA GPU 无硬件/驱动/所需环境时明确不可用，不影响其他功能，也不把已请求的 GPU 静默替换为 CPU。
2. 本地/Docker/SSH GPU 都使用固定获准源码、准确设备 UUID 与实际执行目标；已有正式运行、批准和产物归档链继续生效。NVIDIA 小核必须校验真实数值，设备查询不等于计算成功。本地执行是系统用户权限内的可信执行，文件/网络不隔离、CPU/内存仅调度记账；不冒称容器隔离或宿主硬配额。
3. 同一共享数据目录内，同一 NVIDIA UUID 在本地、Docker、SSH 之间不能重复预留；不同设备可独立使用。不可用/变化/未核验设备拒绝启动，越界设备和无效声明拒绝，未知状态保留占用。占用保证仅覆盖本应用管理的作业。
4. 取消、超时、控制器正常关闭重开、启动响应不确定及监管器失联均不重复启动或误杀复用 PID；确认终止后才释放设备、采集输出。旧 CPU 契约与历史字节不改；SSH 旧协议与在途 handle 保留，新增 GPU 支持不得覆盖仍使用的旧监管器。

复用现有 Run、队列、SQLite 原子预留、固定清单和日志/产物服务。不得为验证自动安装驱动、全局 ML 框架或重启正式研究服务。实际 GPU 验证使用已具备的 NVIDIA 目标与小型确定性任务；无相应硬件/远端环境的路径分别标注未实测，不用模拟替代真实设备证据。
