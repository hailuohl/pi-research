# NVIDIA 执行验收

新增受管 `local` 正式运行和本机运行环境配置，保留固定示例原契约。用户在“资源与调度”保存已有运行时，核对 NVIDIA 设备；Agent 读取脱敏目录，在固定运行契约中声明完整 UUID。Docker 与 SSH 沿用固定镜像及隔离容器，新SSH的CPU/NVIDIA运行使用独立新版 helper，不替换原协议；旧已启动handle仍可观察、取消和归档，旧queued不能新启动，须先取消并更新目标后重新准备批准。设备预留在共享数据目录内跨本地、Docker、SSH 互斥；未知作业保留占用。为兼容无法证明GPU隔离的旧作业，新GPU还会等待所有非终态CPU Docker作业（含开发、文档、文稿）和旧SSH v1作业结束；这是保守并发限制，后续确需CPU/GPU并行时再加入逐作业隔离证明。

本地在当前系统用户权限内执行可信代码，文件与网络不隔离，CPU/RAM 为调度预算；不能当作不可信代码沙箱。GPU 预留只覆盖本应用管理的作业，不控制其他程序。

## 真实设备证据

使用 Python 标准库调用 CUDA Driver，执行固定 PTX 向量加法并逐元素校验，无全局 ML 框架或驱动安装。

| 执行路径 | 结果 | 边界 |
|---|---|---|
| Windows 本地 | 明确指定一张 RTX 4060，4096 个结果、误差 0；完整产物、终态释放及重开读取通过 | NVIDIA；不证明任意训练框架兼容 |
| Docker Desktop / WSL2 | 显式声明三张设备 UUID，12288 个结果、误差 0；完整产物与重开通过 | 本机 WSL2 的单卡请求仍暴露三卡，系统拒绝执行；没有扩大为 `all` 或回退 CPU |
| SSH → Linux Docker 回环 | 独立 GPU 协议，显式三 UUID，12288 个结果、误差 0；完整产物与重开通过 | 隔离回环，非外部授权服务器验收；测试控制端访问 Docker socket，实际实验容器不挂 socket |

原失败保留：Windows NVML 缺 `ProgramFiles`；监管器继承链未传该系统变量；PowerShell 5.1 默认代码页误读含中文/空格的 UTF-8 路径。分别以实际失败、针对回归及修后真实运行闭合。原未知 Run 的清单和占用未删改，未按旧 PID 杀进程或重新执行。SSH 验收环境先被公钥认证文件权限与未创建的工作根拒绝，修正专用测试环境后才运行，没有降低严格主机密钥检查。

独立复核发现CPU镜像继承GPU可见性的越界路径。真实固定镜像带`NVIDIA_VISIBLE_DEVICES=all`、单容器使用NVIDIA runtime时，修前CPU任务可访问3卡；修后同镜像/资源为0卡，显式`void/-1`，宿主默认runtime未修改。新的CPU容器及尚未启动的既有容器都核对禁GPU设置；GPU请求同时固定UUID环境与DeviceRequests。Docker/SSH三UUID运算已按修后代码复验。原失败和原运行记录保留。

## 可移植范围

运行环境使用本机已有程序，不写死开发机路径、账号或 GPU 编号。CPU 不依赖 Python/CUDA；NVIDIA 需要兼容硬件、驱动和用户选择的运行环境。Docker 需要目标引擎支持 GPU，SSH 需要目标已部署匹配的独立 GPU helper。AMD、Apple Metal 暂不接入，其他电脑保留 CPU、Docker、SSH。

浏览器实际保存 Python、核对三张设备、页面重开读取通过；执行环境区域在 320/768/1024/1440 宽度均无横向溢出，控制台无错误。没有改动原在途样式文件或恢复全站布局改造。

备份排除`local-runtimes.json`注册文件，但历史`native-spec.json`仍可能包含本机程序路径和白名单环境；其白名单环境不继承Pi/GitHub认证变量，不用于在新电脑启动程序。缩减终态控制文件作为非阻断后续事项。
