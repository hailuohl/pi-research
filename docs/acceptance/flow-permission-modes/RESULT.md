## 验收条件

1. 四档由 owner 使用版本校验切换，服务器执法并保留历史；重开、服务重启以及完全访问的确认、撤销和未知效果沿实际状态处理。
2. 只读允许已有资料与必要服务记账，拒绝业务变更、新联网和执行；模型会话本身仍由用户发起。
3. 变更前确认显示固定操作及来源，允许本次后由真实 Agent 继续；拒绝、参数/来源/策略变化不能执行，批准不可重复产生副作用。
4. 自动编辑允许既有范围内的私有工作区编辑；命令、新网络范围及正式科研操作保留适用审批，角色、固定来源和已有授权不扩大。
5. 缓存重放、排队、异步结果、子任务和自动唤醒都检查有效策略；旧会话不默默扩权，权限收紧保留实际执行事实和审批历史。

## 边界

没有共享项目写权限扩张，没有启用 Pi 内建工具，没有新增依赖。完全访问仍是同系统用户的本机可信模式，不提供操作系统隔离。前三档通过现有受控领域工具执行，原 WorkingGrant、RunGrant、DiscoveryGrant、TextCorpusGrant 及正式审批继续有效。

正式 HTTP 新主会话默认变更前确认；无策略记录的旧会话保持“现有受控工具”，手动选择后执行所选限制。分支不继承本机完全访问。

## 实际行为

权限守卫放在统一 OperationRegistry，已完成请求重放与异步结果同样检查当前身份和策略。审批复用 ApprovalService，绑定准确输入、来源与权限版本；短续接指令沿原生 Pi 会话回查固定参数，大文件不重复塞入普通消息。只读拒绝文本证据登记等有业务副作用的“读取”工具。

新协作计划的批准内容明确包含任务角色、固定来源及私有输出范围；子任务不会自行扩大范围。旧计划失效后，任务准备和后台 Git 都停止，不能重新捕获新版本洗白。有效计划的 owner 人工重试保留原来源、HEAD 和快照校验，权限变化后仍拒绝。

已单独批准的固定 Run、开发作业可以由独立监督进程继续执行，不能据此恢复宿主能力。保存在只读档上的本机完全访问若派生后台 Git，需要精确操作批准；显式撤权和切档都阻断旧队列。仅连接另一实例不改权限；在另一实例主动降权会撤销持久宿主授权，原实例的受管命令会停止。
