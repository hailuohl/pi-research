# 模型响应超时修复

原 Worker 的 SDK 请求在等待响应头 120 秒后终止，底层 HTTP 传输另有 300 秒响应头及流空闲限制。SDK 与 Worker 内的固定 Pi 0.87.1 HTTP dispatcher 现在共用 600 秒上限：允许较慢的模型响应和流数据间隔，超限仍终止。取消、自动重试关闭和固定模型身份规则保留，没有添加设置入口或依赖。

旧目录配置与受管模型连接都将已知超时转为固定 `PROVIDER_TIMEOUT` 提示。SDK 超时与用户取消保持不同身份；流读取在 SDK 丢失底层 cause 前保留超时分类。任意供应商错误文本、认证信息和请求正文不进入新增超时诊断。原研究计划、成功工具结果及原生会话历史继续保留，失败后不会自动重放工具操作。

真实 Worker、Pi SDK、HTTP/SSE 解析器的隔离回归用测试专用时钟覆盖 130 秒响应、310 秒响应头等待及流空闲、600 秒以上超时、取消、单次请求终态、历史重开和成功工具结果续接。旧版本的 130 秒请求失败已复现。已有流读取错误测试仅调整注入时序，原断言保留；此前研究计划未知字段安全诊断继续验证。

主代理在排除其他在途改动的快照中集中验证，并由独立 Astra 会话复核。现有服务的新 Worker 已加载修复；单独的只读 GLM-5.3 请求成功，无工具调用。原研究会话、已确认计划和原生记录哈希未变，原会话仍使用 max；没有重启服务、改变用户模型配置或重放原研究任务。

实际检查结果、版本及哈希、跳过项、模型配置核验状态见 EVIDENCE.json。原始记录和日志留在忽略目录，不纳入提交。Pi 内部 HTTP helper 和测试时钟依赖固定 SDK 版本，升级时须重新核对；供应商或网络长期无响应仍会触发有限超时。
