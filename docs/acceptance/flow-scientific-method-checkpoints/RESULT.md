## 为什么读过仍然用错

原生记录、操作回执及固定 SDK 的离线消息转换均保留了完整技能正文；未发现本地截断或写入丢字。SDK 的 system.content 为空不表示系统指令丢失，正文位于结构化 sections。历史 HTTP 请求及供应商内部处理没有捕获，不能由此断言远端注意力或 low 档是原因。

可复现的机制缺口是：子资源可以绕过主技能及关键依赖；ready 计划不要求读过当前文件；开发退出码和文件存在性不验证正式指标契约；审查得到包装清单而缺少原始研究输入。修复后，真实审查完整读了材料且给出准确引文，仍遗漏互相矛盾的语句。这进一步表明，读取与引用凭证只能证明材料送达，不能证明结论成立。

## 实际改动

- 技能读取自动附带经过固定版本、权限和摘要校验的主技能与前置方法正文；实验设计入口自动带入科学批判性思维。旧技能发布包保持原样。
- 受控写入后的实际读取生成不可复用的 draftReadId；代理提交 ready 及后续确认、正式捕获都核对当前文件。重写同样字节也使旧凭证失效；缓存重放不制造新读取。
- 新科研开发检查可以声明 metricArtifact。宿主检验实际归档 JSON 是否满足正式有限数值指标契约；不合格作业保留失败记录。
- 主会话实际读过的项目原文随研究计划冻结为 sourceInputs，不扫描或扩大授权。开发修复继续引用历史固定计划，正式运行仍要求当前草稿重新确认。
- 独立审查绑定准确候选、原文和实际测试产物。接受前要求完整读取覆盖、当前任务/尝试的 readId、逐字唯一引文及五项评估；提交、inspect 与后续接受使用同一校验。旧记录不补造新协议或读取证据。
- 独立复核发现并修好了固定简报引用证据漏验、并发读取锚定旧简报两处问题。证据撤销、历史保留、缓存和权限边界均保留。

## 两轮真实 Pi

两轮均使用固定 Pi SDK 0.87.1、zai-coding-cn / glm-5.3 / low、相同研究问题和公开输入。自然任务提示在这两轮之间逐字相同，未告诉 Pi 发现的科学错误或修法；操作者执行准确审批及阶段通知。相较上一批提示，仅将禁止助手改为有界开发检查与独立审查授权。

第一轮使用技能包 `40fedddf…`：八种方法正文随依赖送达，草稿有当前读回凭证，合成检查成功，但独立审查没有原始来源，并漏掉自测旁路、重复记录导致区间虚窄等问题。停止正式运行，保留原 accept 记录后修复审查机制。

第二轮使用 `eaedaaa0…`：主会话实际收到完整 CSV 和其余原文；审查必读材料 9/9 完整，21 条引文均与实际片段匹配。前三次开发检查分别因语法、合成分层空训练集、错误字典字段失败。操作者明确把开发额度从 3 增至 5，未提供错误位置或答案；Pi 自行修复，第四次检查成功。因此它不属于原预算内或全无人介入成功。

独立复算确认：20 项合成指标、400 条预测与代码一致；自测和正式入口共用计算与序列化路径；精确重复记录在划分前去重。五类旧阻断的情况如下：

| 原问题 | 第二轮观察 |
|---|---|
| 指标为嵌套或非数值格式 | 实际归档通过有限数值契约，20 项独立复算一致 |
| 无方差依据却预测精度/功效 | 未再次出现；未知量保留为未知 |
| 自定阈值被当作领域效用 | 旧普遍化断言消失，2% 仍只能作为未验证的操作判据；另有判定分支冲突 |
| 同 DOI 被推成同一研究 | **仍阻断**：protocol 第51行与第54行相互矛盾 |
| 仅改评价权重却泛称敏感性验证 | 本轮未声称已完成敏感性验证，重复划分明确留给后续获批工作 |

另一个阻断是 protocol 第35行把未达到两个增益条件的改善判为“无实际增益”，而 compare.py 第143–144行判为 inconclusive。用 1% 改善且区间下界为正的反例即可复现。内部审查虽然 accept，外部验收不接受其科学结论。另保留阈值含义、静态样本量注释和序数尺度解释三个非阻断限制。

主会话随后只收到“独立审查已结束，请按真实记录继续原任务。”，实际回查内部 accept 并申请整合候选。操作者未批准该整合，未发送外部科学答案；协议中的两项阻断仍在。两轮正式 Run、真实数据拟合和最终科研报告均为 0；不能用合成结果回答红酒研究问题。

## 验证与边界

实施请求 Sol xhigh，关键独立复核请求 Astra xhigh；工具未回显实际模型/档位，记录为“已请求，运行时未回显”。Pi 配置及原生会话元数据另行留存，不等同供应商推理实现证明。

本批不修改前端布局、主会话模型、全局设置或五个既有在途文件。历史失败候选、原 accept、原生日志及数据库保留在本地 `.validation`，不进入 Git。提交的 [evidence.json](evidence.json) 仅保留必要身份、摘要和验证状态。

## 独立 high 诊断

另外完成一次隔离、只读的真实 Pi high 诊断，审查同一固定候选及 13 份完全相同的原文/测试材料，不提供已知两项阻断或原 accept。它使用新项目的只读协调会话、通用审查提示及 artifact_read，角色、提示接口与原 reviewer 不完全相同，因此仅用于定位，不能归因于档位差异，也不计作原无提醒流程通过。

诊断给出 disputed，正确发现判定分支冲突和硬编码 n_test>300 注释，却仍漏掉“同一研究”矛盾。它声称 13/13 完整阅读，实际只有 12/13：CSV 中 [48000,64000) 的片段未读取。这一诊断没有正式 reviewer 的读取覆盖门槛；原流程的 9/9 是有完整凭证的。不能把提高档位当作已验证修复，也没有将这份诊断答案反馈给原 Pi。
