# UI-EMPTY-08 · 复用未发送的新会话

基线：`b954d3ac49755224535d2de6717d86b670229f62`。本批只修改“新建会话”入口及相关回归检查，没有布局、后台接口、授权、依赖或数据删除改动。

## 固定验收条件

1. 当前项目已有未运行、没有任何消息的普通主会话时，优先复用当前会话；重复点击不新增，当前草稿、附件及模型选择保持。
2. 任意发送、排队、失败、取消/移出队列、系统及自动消息历史都阻止空白复用；没有合适空会话时沿用正常创建。
3. 不误用其他项目、归档项目/会话、任务、团队、分支或已启动会话；查询/创建失败保留原视图，可重试；卸载及项目 A→B→A 的迟到响应不接管视图。
4. 重开及空会话超出最近列表时仍可找回；同一页面同 tick 连点只启动一个流程，移动导航关闭与聚焦保持。

## 实现

先读取新鲜项目状态，再校验当前会话元数据并用既有 `/messages` 全历史接口确认空白。若当前会话不合适，按项目范围分页查找主会话，验证候选后复用。未找到才发送原来的 `/sessions` 创建请求。

复用条件包含 idle/coordinator、无任务/团队/分支、尚未启动原生会话、generation/lease 为初始状态，以及全历史为空；不使用当前聊天窗口或分页空数组判断。同步入口锁防止 React 更新 busy 前重入，项目切换标记阻止旧响应接管。同 id 的 Chat key 保持，模型和已有配置不改写。

## 验证

旧产物相关检查：28 项中 19 项通过，新增 9 项回归失败；修复后 28/28 通过。全量回归 1045 项，1022 通过、0 失败、23 跳过，退出码 0。干净安装、构建、类型检查均退出 0，507 个分发文件一致。旧断言保留，仅适配新增读取请求的 mock。

隔离合成项目实际页面：修复前，已有空会话再次点击使会话从 5 个增至 6 个；修复后重复点击保持 6 个及同一 ID，未发送草稿和所选 minimal 模型保留，项目默认仍为 off。从有历史的会话点击新建，会选回现有空会话而不新增。通过本机固定 SSE 的真实 Pi 发送后，该会话有 2 条消息；没有其他可复用空会话时，新建正常增加 1 个。重开及手机导航中再次点击保持会话数与 ID，导航收起、焦点返回按钮。

正式 4794 页面已加载对应 main.js，实际 HTTP 200 产物哈希与本批编译文件一致。后台服务与已有作业未重启；没有外部模型调用或真实用户数据测试。布局验证复用上一批证据，本批 render 与 CSS 未改。

独立复核及机器摘要见 [evidence.json](evidence.json)，原日志在 `.validation/ui-empty-session-2026-10-04/`。五个已有在途文件保留且不暂存。

边界：复用查询沿用既有 API，候选较多或未运行会话积累大量已取消消息时可能较慢；未增加后台空白查询接口。同步锁只防同一页面重入，未新增多个独立标签同时首次创建的全局事务互斥。附件保持由同 id 的组件契约检查覆盖，未执行物理文件选择；其他浏览器引擎未实测。
