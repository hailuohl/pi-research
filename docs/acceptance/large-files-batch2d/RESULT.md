## 实际变更

- 默认 workspace_read 与显式 workspace-text-v1 分页都先记录 pending。项目小原文与受管草稿均通过原真实 SDK resultDigest/worker/代际/权限/epoch ACK 后才满足新接受条件；分页保留 BOM、CRLF、Unicode 和完整原文摘要。
- legacy 项目输入使用独立持久选择，跨 clarifying 保留；未送达的新选择不会被固化，也不能经 clarifying → ready 绕行。新选择参与匹配审批指纹，ACK/cache 不改选；同内容可复用 artifact，但新引用保留新 binding readId。
- 新 ready 草稿严格要求完整送达覆盖和当前 writeVersion/现场摘要。历史兼容只能由服务端加载的完整原 brief/原操作提供，原 payload/digest 不重写，Owner 手动省略行为保持。
- 原准确批准通知的 inspect → 原工具路线、execute/resume 与已完成精确重放保持。合法自动续接沿既有 human-origin/permission 授权读自己的受管草稿，保留真实 wakeup/continuation/message/代际及不可变来源；不同权限链不混拼页，项目输入选择仍限普通主协调者。
- Host 保留真实自动派发消息，同时不把自动消息标成人类输入。新的人类输入消费后使用单调保护，旧事件重放不能恢复旧自动授权来源，已捕获调用不被后来事件改写。
- 新写入前映像按既有内容/元数据预算稳定读取，写前及恢复比较流式处理目标和备份。末尾文件身份、大小、时间、mode 与原期望一致性一并检查，保留并发改动、journal/backup 和不同 inode 手工恢复语义。Windows 既有排除名及 .env.* 按大小写不敏感规则匹配；POSIX 原语义保留。

接口见 `docs/api/workspace-read-delivery.md`，五项验收及兼容裁定见本批 spec。
