# Agent 查询准确提交的同步回执

本批唯一流程：完成受管本地 Git 操作后，交互主协调 Agent 用真实完整 SHA 查询本项目已保存的 GitHub 同步回执，准确说明本地完成与远端确认的区别。沿用现有私密仓库创建/自动同步，不扩展 Agent 的 Git 写入或网络权限。

1. `project_inspect({githubCommit:<40位SHA>})` 返回仅该项目、该准确提交的有限回执；同 SHA 多个 ref 分别呈现状态与记录时间，最多 20 项并有 hasMore。无记录不等于失败；synced 是保存时的确认，不是远端实时检查。
2. 用户和交互主协调者可查询；Task/wakeup、非交互协调者、其他角色、跨项目不能扩大读取范围。原无参数 project_inspect 行为保留。输入拒绝 URL、路径、简写 SHA 和额外字段。
3. 相同 callId 重查获得当前保存状态并重新授权，不覆盖旧回执；幂等输入冲突仍拒绝。重开后准确 SHA/ref 与旧操作历史保留，查询不暴露账号、仓库私密路径、原始 stderr、源码或其他项目信息。
4. 查询不运行 gh/git、发网络请求、创建或恢复同步任务、推送、探测连接状态。纯读取服务复用 readSnapshot；已有 Agent 审计事务沿用。
5. Git 技能给出符合真实 Pi 参数包装的本地操作→同步回执示例，等待/unknown/failed 的解释与现有用户恢复入口。离线真实 SDK 或领域服务前向接线证据，与真实远端 GitHub 实测分别记录。
