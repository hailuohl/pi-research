# Agent 查询运行调度状态

本批流程：交互主协调 Agent 读取一个正式 Run，解释当前排队、GPU 预留和恢复原因，然后依据真实状态等待或请求用户补齐前置条件。沿用现有运行审批、队列和监管器；前端布局继续暂缓。

1. `run_inspect({runId,includeScheduling:true})` 返回本项目单个 Run 的调度观察，复用调度器的原因计算；终态及旧无队列记录明确返回不可用原因，不保留过时等待原因。不泄露其他作业、全局用量、目标 context 或宿主路径。
2. 调度扩展仅用户及交互主协调者可读；Task、wakeup、其他角色和跨项目访问被拒绝。无标志或 false 的旧查询保留原合同与权限。
3. 相同 callId 重查及关闭重开读取当前状态，权限重新核对；不同输入仍拒绝幂等冲突，旧回执、Run、manifest 和固定源码不被覆盖。
4. 查询只读已保存状态，不探测硬件/目标、不联网、不启动执行、不修改队列或配额。
5. 计算技能按 local/Docker/SSH 分别路由，例子符合真实工具 schema，说明批准、最新观察和失败处理。使用真实固定 Pi SDK 前向验证工具结果到达模型路径；离线模拟供应商与真实外部模型验收分别记录。

请求实施模型 `gpt-6.1-sol/high`；独立复核模型按最终权限与回执差异选择。接口接受配置但没有运行时回显时，记录为“已请求，运行时未回显”。主代理负责集成、全量回归、干净构建、提交及私密远端同步。
