# 本批验收：报告历史有界分页与精确回查

范围：为项目内已保存的报告增加 owner-only `report_list` 后端操作，以稳定 SQLite 游标返回有界摘要；选中报告仍由现有 `report_inspect` 重新校验来源有效性。沿用上一批 Run 分页的查询模式，不改报告生成/导出、旧项目总览或前端。

1. **成功路径。** Owner 按项目、游标及 1–100 的页大小读取报告 ID、标题、格式、创建/更新时间和来源计数；从实际 Wine 报告历史选中一项，以 `report_inspect` 回查同一 ID、当前完整性与固定引用。页响应不展开绑定清单、正文或宿主路径。
2. **边界与失败。** 非 owner、错项目、非法或超大游标/页大小均不泄漏另一项目报告，也不修改记录、运行或调用模型。旧版报告缺少生成时标题/格式时采用既有历史展示语义，不伪造当前有效性。
3. **稳定续页。** 已返回第一页后新增报告或更新旧报告不会移动 rowid；后页不重不漏并明确末页。列表仅显示持久摘要，是否 `current/stale/legacy` 以所选报告的 `report_inspect` 为准。
4. **重开与交付。** 关闭重开后同一游标继续得到相同 ID，原报告/Artifact 字节和 Run 来源不变；本批不启动 Pi、Docker 或新报告。开发仅跑相关检查，集成后一次全量回归、干净构建及独立常规复核；真实后端 HTTP 仅走这条分页→选中流程，前端不验。
