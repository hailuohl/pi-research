# PR13：固定源码经 SSH 运行并回收

新增可用能力：用户通过本机 `ssh-target configure/probe` 固定 SSH 主机密钥、身份文件和远端 Docker 引擎；实验选择目标别名后，`RunIntent` 冻结源码、镜像、资源与目标摘要，仍需单独批准。提交后按唯一远端 handle 执行，日志、指标、声明产物及失败历史回到原 Run。私钥和宿主路径仅留私有配置，不进入 Run、执行回执或离线备份。开工前固定的五项验收覆盖成功、无批准/越界、取消与断线对账、重开回查及集中验证；Slurm 和完整远程工作台不在本批。

隔离回环 SSH→Linux Docker 实测 Run `e92fa959…` 为 **succeeded / complete / exitCode 0**，五点预测的 MSE 为 0，六项固定产物按摘要核对；控制器在运行中关闭再打开，仍回查同一 handle、同一容器，`start-events.txt` 只有一次启动。容器实测禁网、只读根、非特权用户、256 MiB/64 PID，未挂载 Docker socket 或身份文件。未批准提交被拒；路径、主机密钥、撤销、容量、取消和丢失回执的边界由相关回归覆盖。浏览器刷新后仍可读日志、CSV 与历史，并已触发下载。

两条真实失败也保留：首个回环目标的嵌套 Docker cgroup 配置使容器只到 `created`；按完整 ID 和原标签人工退役后，旧 handle 终态失败，未重提。第二目标首轮因非特权进程试图 `chmod /work` 而退出 1；修正为仅处理复制的子项后，才执行上述成功 Run。旧版在途监管进程曾把首条 Run 的具体远端失败原因简化为“缺少产物”；远端原记录仍在，历史本地回执不改写，新版已用失败先现、修复后通过的回归保证保留原错误。

剩余：用户暂无外部授权 SSH 主机，因此这里只证明隔离回环，**不**给外部主机、Slurm 或远程工作台的 live 项打勾。工作台旧实验详情仍把 SSH 标成 Docker，受保护的前端布局文件本批未改；远端嵌套源码目录在限制性 `umask` 下的权限检查留后续待办。见[单份机器证据](evidence.json)；原日志、私钥和测试数据库留本机忽略目录。

验证：全量 826 项中 803 通过、22 跳过、1 项在旧编译产物上暴露 RunGrant schema 兼容问题；修复后仅重跑受影响的 13 项，全部通过。隔离干净安装与最终构建通过，465 个产物，独立 Astra 复核的唯一阻断已关闭。本批没有调用 Pi，也没有覆盖原工作区 12 处在途改动。
