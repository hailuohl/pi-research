# 保留冻结身份的异址迁移

已实现离线 A→B→C 迁移：新文件使用 `pi-data:/` 引用，旧绝对引用通过所属数据库的位置记录解析到当前目录。旧业务记录、批准与清单摘要、原生 Pi 历史不重写；受管 Git 工作副本的位置指针单独迁移。未知根、损坏映射、越界引用与链接明确拒绝，旧目录存在时也不回退读取。

```powershell
node dist/apps/cli/index.js backup create --data "D:\PiData" --out "D:\PiBackups\saved" --offline
node dist/apps/cli/index.js backup restore --data "D:\PiDataNew" --from "D:\PiBackups\saved" --offline --relocate
```

先停止源控制器与其他 CLI，目标必须不存在；迁移后只使用新副本，原件保持离线。不同数据库副本不共享提交额度。备份保留私有研究正文和日志，认证文件排除；当前只支持同一平台。

实际旧数据完成两次 CLI 迁移：A 的 53 条记录、48 个非数据库文件保持不变；B 通过现有用户接口新建私有文件与产物，C 首次重开保留全部 56 条记录和 7 个可读产物。98,774 字节的原生 Pi 文件摘要及原生 ID 未变，安装的 SDK 离线打开时使用 C 的运行目录。浏览器回查 14 条旧消息、2 条新本地消息及新旧产物，刷新保留列表。产物预览选择在刷新后重置，记为后续非阻断项；未评估布局。

Docker Desktop 起初因 `sailor-ingest.sock` 无法访问而未启动；旧会话的固定技能预检在 worker 前拒绝了模型派发。用户恢复 Docker 后，先确认 C 的旧控制器空闲，取消那条未派发消息并通过原重试入口发送。真实 Pi 在 C 的物理工作区和会话目录续接**同一原生 ID**，原生文件前 98,774 字节保持不变，在 C 写入新私有文件；原 A 不回退读取或写入。原技能包绑定、待交付通知及单份递送回执保留；此次有 2 条成功的受管模型 HTTP 请求。

另行准备、核对并批准一次固定 Python 开发测试；真实 Docker 容器的受管标签与清单摘要相符，挂载来自 C，退出码 0、完整成功，归档图像、CSV、检查 JSON 及日志共 6 个产物。A 的 48 个旧文件、B 的 49 个旧文件均与原摘要一致；C 的 74 条当前记录中，A 原有 53 条仅会话行因获准续接改变，其余 52 条原字节未改；从 B 备份带来的 56 条旧记录中，54 条原字节未改，另两条是会话与合法取消的未派发消息。浏览器实际看到旧消息、续接回复和新测试终态，刷新后仍可回查。初次 Docker 启动失败原样留证；有[相似故障报告](https://github.com/docker/desktop-feedback/issues/675)，不据此确定本机根因。

独立 Astra 复核发现一处 WorkingGrant 执行门仍读取旧快照路径，已仅在 I/O 边界修复。回归在 A 文件全部被污染时调用真实执行授权校验：修复前失败，修复后通过；永久提交计次、越界拒绝及 B→C 保留一并覆盖。复制的旧版未完成写入日志也不能触碰 A。前端布局改动保持暂缓；后续范围以当前实施计划为准，本批不扩入分发或托管服务。

集中全量772项：749通过、1失败、22跳过。唯一失败是旧文件交接夹具的故障注入未解析URI，修正后受影响3项全部通过；没有重跑全量，也没有削弱原损坏断言。新迁移相关8项、其他适配相关219项通过；干净安装/构建/类型检查通过，450个文件一致。后续真实验收没有修改产品代码或重跑全量。暂缓布局的3个生成文件不进入本批提交。

独立 Astra 对新增真实执行证据做了定点只读复核，确认条件 4 的真实 Pi/Docker 缺口已关闭，无具体阻断；真实 C 数据本身没有 WorkingGrant，有限计次仍以此前通过的 A→B→C 集成测试为证。详细验证状态见[机器证据](evidence.json)。本批只保留本记录和该证据文件，不复制原始日志、截图或私有数据。
