# 目标机器上的真实 Pi 验收清单

当前状态：未执行，不是通过记录。执行这些步骤可能产生模型费用，需由操作者明确选择自己的供应商和预算。

1. 使用 Node >=22.19.0 安装固定 Pi 0.87.1，并记录生成的运行时锁文件摘要。
2. 配置真实模型与凭据，创建新主会话。发送一个不需要外部副作用的问题，核对实际模型、最终消息、供应商用量与错误。
3. 中途发送 steer 与 follow_up，分别核对行为；中止后不应再接受同代次工具写入。
4. 关闭/重启控制服务后恢复指定 Session 文件，不允许选择“最近会话”串到别的任务。
5. 开启协作，批准两个具有独立明确输入的只读任务。检查每个任务有不同 Session、工作区和租约；不是角色提示词在同一会话中轮流输出。
6. 验证助手不能创建其他助手、访问未分配证据、批准实验、执行默认 Shell、写共享目录或调用未经授权的模型。
7. 提交关键结果，必须等待独立审查后下游才能继续；不存在的引用不能被采纳。
8. 关闭协作时，未启动任务不得继续偷偷启动；已运行任务收尾可见。观察实际费用，而不是只看任务尝试额度。
9. 另行批准随包数值实验；停止 Pi 后 Run 应仍受独立 Runner 管理，结果可对账。
10. 记录所有失败、用量与误差。不得把单次成功、模板产物或 Fixture 当作真实科研能力提升的证据。

真实多 Agent 与单 Agent 对照、DFT/ML科研协议及远程计算属于后续独立评测，不在这份小型接入检查中冒充完成。

## v0.2 结果唤醒专项（尚未真实执行）

先记录期望使用的模型、数据范围和可能费用，使用自己的独立测试项目：

11. 创建开启autoAnalyze的活动，批准基线Run并等待完成。确认数据库先出现通知，模型可用后只有一次实际主会话分析；核对Session文件、assistant消息的wakeupId以及供应商实际用量。
12. 主会话忙时完成另一个Run，再发送用户消息。应先处理用户消息；未处理结果不能丢失。自动分析期间steer/follow_up应排队，而不是被注入当前权限收窄的执行。
13. 自动分析只能读取获分配的证据和提出决定；构造run_submit/agent_delegate/未分配evidence调用应被宿主拒绝。提交决定后必须人工批准应用，新Run还需另行批准。
14. 选择autoSummarize的团队，完成两项独立任务与所需审查，检查最终综合来自真实Pi消息，而不是系统统计文字。API未填写autoSummarize以及旧团队不自动调用付费模型。
15. 暂停/取消/变更来源时核对执行、预留、未知用量和队列状态；中止控制进程后重新启动，不自动重发不确定是否已计费的调用。
16. Pi返回空内容或供应商错误不能显示为综合完成。网络中断后只在明确点击重试后再尝试，最多2次；检查不存在额外未记账调用。

若任一步失败，应记录实际SDK/模型/系统版本、错误和真实请求次数。现有fixture IPC测试不能替代这些检查。
