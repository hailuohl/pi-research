# 第3A批：正式实验结束后的原对话分析

本批接通普通主会话 Run 的一次结果分析。后续轮次和文稿交付仍按后续批次验收，不把一次模型分析视为科研结论。

## 验收条件与实现

1. `run_prepare.autoAnalyze` 默认关闭；开启时将原主会话、固定模型和最多一次 Pi 分析任务纳入运行清单及原对话批准。一次任务可能包含多个模型 HTTP 往返，不授予下一轮计算。
2. 只有该清单的真实终态 Run 可以产生通知。重新调度、重开或结果变化不会产生第二份通知；RunGrant 和 Campaign 成员沿原有路径处理。
3. 分析只能读取该 Run 的实测指标、日志和归档产物。失败、缺失或无效结果明确标记；不读取原研究问题正文、其他 Run 或原会话原生历史。
4. 分析使用独立原生模型会话，结果写回原主对话；原交互式历史路径保留。模型变化、撤销批准或归档会阻止未开始的分析，已完成的正式 Run 保留。
5. 确定未创建模型进程的失败仅能由用户显式重试；已创建进程或不确定用量不会自动重试。事务登记失败保留进程槽位，确认退出后释放。

## 验证

新增回归在修复前暴露 `generation=1` 导致用户无法恢复的问题；另覆盖实际 fork 返回后 SQLite COMMIT 失败的回滚边界。相关检查通过，独立 Astra 复核修复通过。完整检查及干净构建统计见同批机器证据。

实际 `zai-coding-cn/glm-5.3` 在原对话准备并等待批准；批准后受信本地数值程序真正完成二阶复核，指标为 `mse=0.000446210591122142`、`r2=0.9996130253960532`、`train_mse=0.00045146486373746783`。随后一次独立 Pi 分析完成并回到原对话。重开仍可读取，之前未启用分析的三次运行未自动调用模型。

原始测试日志、模型历史和数据库留在忽略的 `.validation`，不进入仓库。只提交精简机器证据。
