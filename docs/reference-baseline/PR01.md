# PR01 对标矩阵与证据边界

[`capability-matrix.json`](capability-matrix.json)逐项沿用 `packages/contracts/capabilities.ts` 的 21 个能力 ID，并把原设计 M0–M9 和实施计划 PR01–14 映射到这些能力。`alignment` 只说明目标与固定上游的关系：`exact` 表示目标行为相同，`equivalent` 表示用户能力相同但内部实现不同，`intentional-deviation` 表示有意保留的差异。即使一项标为 `equivalent`，也不表示当前实现已经等价；是否可用须分别查看代码、配置、契约测试、目标环境集成和用户旅程五维状态。矩阵列出的测试文件是可复核的测试入口，不是本轮测试通过记录。

上游基准固定为 `alphaXiv/OpenResearch@3037f727e80e0ab20c61a87c613a50dde009a835`，源码阅读范围与 blob 身份见 [`OPENRESEARCH-COMPARISON.md`](OPENRESEARCH-COMPARISON.md) 和 `third_party/openresearch/source-manifest.json`。两份原始 ZIP 的 SHA-256 分别为 v0.2.3-fixed-skills `cf648fa86d39024d55914af421d9899c7f1f968bf549ca67d1bdae29374dd4fa`、v0.3.1-experimental-skills `5dee66f094f42353c5ac1d47387ae30fa4e65bafde11b3ff10f39542ff591f1c`。这是 ZIP 文件身份，不是解压目录或 Git 提交的摘要。

本轮两版干净安装、构建、类型检查、完整测试，以及预构建包无依赖启动记录见 [PR01 验证记录](../acceptance/pr01/RESULTS.zh-CN.md)。真实 Pi 验收须记录固定 SDK 的工具调用、流输出、引导、中止、关闭后按精确会话文件恢复、实际模型、原生会话与用量；`tests/unit/pi-sdk-contract.test.mjs` 的真实 SDK 离线契约检查也不能代替供应商调用。无凭据或未执行时保持 `unverified`。固定上游应用未启动，M0 页面与交互基线截图仍为空；不凭静态源码推断逐屏一致。

矩阵是当前代码的范围索引，未实现的 PR02–14 目标仍保留为缺口。实际验收记录应独立写入 `docs/acceptance/`，以可复核命令、环境和原始输出更新五维状态；不能从测试文件存在、接口返回成功或确定性示例推断真实科研能力。
