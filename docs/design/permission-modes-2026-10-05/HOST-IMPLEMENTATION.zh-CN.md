# 本机完全访问实施说明

用户在设计交付后要求“请你就绪”。本批按照此前“系统用户权限内的宿主文件、命令与网络”定义，接通**本机可信完全访问**。真实会话默认不开启；需在对应主协调会话明确确认后启用。这里替代原设计中“完全访问只能在强控制面隔离后开放”的实施取舍，原强隔离方案保留为不同执行边界的后续选项。

## 已实现的流程

输入框下方的“完全访问 · 可启用” → 阅读本机未隔离范围并勾选确认 → 启用 → Pi 使用 `host_execute` 执行真实程序、文件和网络操作 → 原入口撤销。

- 仅普通、未归档、没有既有固定范围授权的交互主协调会话可启用。子任务、自动唤醒、其他角色不自动获得此工具；已有 Working/Run/Discovery/TextCorpus 授权的会话需使用新的普通主会话。
- 保持 Pi builtin 关闭，真实命令经 `ToolDispatcher → OperationRegistry → HostAccessService`。使用 argv 原样参数、绝对 cwd、真实进程和持久回执；默认 30 秒、单条最多 60 秒，同会话一条受管命令，stdout/stderr 各保留最多 64 Ki 字符。
- 不自动继承服务端 PI/model 凭据或 NODE_OPTIONS。**这不是凭据隔离**：该系统用户能读到的文件和第三方凭据仍能由命令访问。
- 托管入口验证角色、会话、generation、租约、授权 runtime/epoch、项目生命周期和固定范围绑定。相同调用标识不重复执行；失效 epoch 或未知旧执行不能靠重放或新 callId 绕过。
- 撤销立即拒绝新准入，停止能跟踪的命令树。已写文件、已发请求与脱管进程无法保证还原/清除。停止或记账未确认则保守标 unknown，并封锁新执行。
- unknown 包含可确认的 PID。重新启用前，用户需另勾选“已核对未知命令的进程和外部效果”；新授权记录所核对的未知回执 ID。旧回执不删除，旧 epoch 仍不能重放。
- 授权绑定当前服务执行端，重启/切换执行端不会静默恢复。普通 ResearchApp/后台 worker 的连接不修改其他控制器在跑的记录；外来非终态仅保守显示为当前实例未确认。
- 终态与审计事务化。写入失败也令 Promise 收敛并留下内存不确定屏障；启动已发生后的记账/恢复双失败同样不能解除屏障。
- Worker 下发的工具集合只用于收尾诊断与活动显示。撤权后的真实命令仍须记录失败终态，诊断集合不能授权新的执行。

## 真实边界

这是同系统用户的可信执行，`osSandboxVerified=false`。命令能访问该用户的应用 DB、服务代码、认证文件、owner HTTP、进程及第三方账户权限。托管 API 的角色/版本检查和用户确认按钮**不能**作为抵抗这些命令的强安全边界；模型不能自行审批是使用约定，不能在 raw host full 中声称由 OS 隔离保证。

托管路径保留执行历史与回执；本机 full 可接触同用户数据，因此不宣称审计防篡改或冻结来源在原始宿主文件操作下不可修改。领域正式运行、采纳和发布工具沿原批准流程，raw 命令本身的系统可达范围不受这些领域接口限制。

若要求保护应用控制面免受 Agent 访问，应采用独立安全主体/可信 owner 通道，或明确限定宿主挂载范围的隔离执行环境。不能把容器工作副本称为整个 Windows 完全访问。

## 本批范围

只把“完全访问”变成实际可用流程，不声称原型中的前三档已完成统一 effect 分类与逐次审批实施。正式页面保留现有受控领域工具行为，并提供真实的完全访问开启/撤销入口；原外层布局、来源、附件、多智能体、模型和发送位置保持原尺寸。

验收条件：

1. 显式启用后，真实 Pi SDK/worker 与真实进程完成文件、命令、网络路径；不存在只改静态标签。
2. 托管 API 的角色、task/wakeup、lease、epoch、固定授权绑定与重放校验有效；未隔离边界如实可见，不冒称 owner 数据受到隔离。
3. 撤销/中断/超时与记录故障拒绝后续命令，已发生事实保留；未知状态需用户核对，新 key不自动释放。
4. 重启不恢复 full，后台连接不误改仍在跑的状态；布局和确认流程可走通。
