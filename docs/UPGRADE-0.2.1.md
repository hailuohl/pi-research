# 从 v0.2.0 升级到 v0.2.1

核心数据库仍使用原 records / events 等表，不批量重写旧 Run、产物、Session 或文件路径。本版增加 change-proposal、run-outcome-review、session-context-delivery 等对象，旧程序不理解这些对象。

## 升级顺序

1. 停止旧 Agent、控制服务以及所有 Runner 写入；等正式 Run 结束或先正确取消并对账。仅关闭浏览器不算停机。
2. 备份整个数据目录，包括 SQLite/WAL、项目、快照、会话、产物和令牌。不要只复制 state.db，也不要上传含凭据备份。
3. 把新程序解压到新目录，不覆盖原始程序和数据。`.env` 的 `PI_DATA_DIR` 设置为**原绝对数据目录**。旧记录保存绝对路径，不能任意移动或用 Windows 路径替换 WSL 路径。
4. 在新目录执行 `node dist/apps/cli/index.js doctor`，确认版本/路径。随后启动 `node dist/apps/server/index.js`。
5. 核对旧实验、运行、快照、报告，优先用新建一次性项目测试变更提案和结果评议；不要在重要未备份的研究数据上验证升级。

## 行为变化

- 不满足新的提交/验收依赖校验的旧活跃协作计划会暂停，并说明原因。应创建并批准新计划，而不是直接改数据库绕过检查。旧结果保留；新版本不会从自然语言目标中猜造历史 expectedOutputs。
- 过去被提前 accepted、但还有声明审查者的任务，会在新分配前重新等待这些审查意见。已形成的历史产物不会被删除。
- 无有效数值的已结束运行，不自动等同于无结果失败。需要在实验详情解释它是否回答问题；确认未回答后再修复/重跑，确认已回答则保护代码。此评议不会修改进程状态、产物完整性或判定假设成立。
- 恢复工具幂等读取兼容旧代次键；如旧版本已经造成多个相同调用的不同业务结果，新版返回 `LEGACY_OPERATION_AMBIGUOUS`，要求人工核对，不擅自删除历史对象。
- 模型通知采用至少一次交付。未收到确认的通知可能再次交给模型，始终携带稳定 ID；不能据此宣称外部模型请求绝不重复计费。
- 已有项目不会自动开启多智能体或自动分析。旧Pi运行时与模型配置仍需自行按README接入；本包无密钥。

## 回退

停止新版全部写入，恢复升级前完整备份，然后运行旧程序。不能让旧调度器写入含新对象的新数据库；新版产生的研究需单独保留，不能期待自动合并回旧备份。

验证范围限于停机后同路径接管的受控测试。不是跨操作系统、搬目录、并发双版本或任意真实用户数据库迁移认证。
