# CFLOW-01 协作计划与失败恢复

状态：源码、自动检查、独立复核与 Chrome 关键路径验收完成，原4794运行版本已更新；本记录随本批代码交付。

## 范围与验收

1. 无效图、审查门、预算和固定输入在审批前拒绝，不产生新操作审批、团队、任务或额度预留。
2. 合法计划准确批准后最多启动一次；已批准但启动请求失败时，刷新能继续启动，不再次审批。
3. 失败只能显式按额度建立独立新尝试；旧 unknown 用量和旧回执保留，迟到输出不能接纳。
4. 重试按钮使用服务端同一资格守卫，显示耗尽或失效原因。
5. 刷新和重开保留原批准、尝试、错误与结果；界面提供最近至多10次历史摘要，不输出工作目录或原生会话字段。

科研任务及前端布局保持暂停。保留原有9个未提交文件中的在途改动，仅集成本批功能差异；无数据库迁移、权限扩大或新增依赖。

## 实际改动

- TeamService 复用无写入计划校验，两个委派操作在具体操作审批前校验，创建事务内重新检查。
- retry 与只读资格投影共用派发、状态、尝试及预算守卫，保留综合额度和 unknown 预留。
- 已批准待启动的计划继续显示启动入口，只提交 activate。
- 用户项目视图增加有限尝试历史；严格 task_inspect 工具合同保持原样。
- 历史用短尝试ID标识，不把执行 generation 误称为尝试次数。
