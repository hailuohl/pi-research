## 结果与边界

1. 开发与正式 Docker 监管共用完成时间判定。运行态检查当前时间，退出态使用容器 `FinishedAt`；按时完成但较晚观察仍成功，达到预算或开发 deadline 的退出不能成功。缺失、非法或早于开始的时间按不完整失败处理。保留已经确认的取消/超时原因，不新增取消交错语义，不改写历史终态。
2. 当前独立开发 reviewer 可通过原 `artifact_read` 分页读取固定 stdout/stderr 的后段，最多为批准的 `logBytes` 且不超过 16 MiB，每页仍 16000 字符。例外同时核对当前任务、批准、来源、归档摘要及最初审查 wrapper 的日志身份；普通产物仍限 2 MiB，不开放生产者会话。非法 UTF-8 返回固定领域错误。
3. 非预期工具异常产生关联诊断 ID。本机记录位于数据目录的 `sessions/<sessionId>/diagnostics/<diagnosticId>.json`，只保存受控错误类型、错误码、系统调用、应用相对栈位置及调用 ID 摘要；不保存原始消息、堆栈行、输入、任意属性或凭据。公开与模型输出只附不透明 ID。路径从可信数据根检查，创建失败明确提示未保存，原工具失败不被覆盖。Windows 沿用既有数据目录权限边界，POSIX mode 不代表 Windows ACL 隔离。
4. 所有**新准备**的正式 Docker 运行清单均冻结 `manifest.threadLimit`，包括旧实验。新根 Docker 合同也保留线程约束。旧合同及 contractDigest 不变；已批准旧 intent、Run、旧授权和新授权包含的旧 intent 均不补字段。Docker 只使用冻结的清单值或合同值，拒绝非法值及两处冲突，不在执行时动态回退 CPU。正式范围 1–64，开发仍为 1–8。回执、授权检视及固定报告引用同步冻结值。

线程变量是库默认设置，不增加 CPU、PID、内存或网络权限，也不保证任意程序遵守。没有数据迁移、依赖增加、原生对话改写或科研重跑。
